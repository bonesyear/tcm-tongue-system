## 1. 总结论

### 1.1 值得保留的基础

当前项目已经有可工作的记录兼容层、六维数据模型、拍照与手动双通道、备份机制、危险拦截、当地规则速览、知识检索和较完整测试。以下方向不应推倒：

- `src/` 仅标准库、数据默认留本机、无遥测；
- `DailyRecord` 对形状 A/B/C 的读取兼容；
- 用封闭词表约束模型输出的意图；
- 修正前备份、危险信号要求人工复核；
- 无辨证模型时明确标注“本地规则速览，不是辨证结论”。

### 1.2 根本问题不在“缺多少词”

当前最主要的问题是：**观察事实、用户声明、评分结果、证据覆盖、医学严重度、预警结论和 LLM 派生报告之间缺少稳定的边界。**

由此产生四类系统性后果：

1. **未知被当成正常**：词表未命中与明确正常都返回 0，进一步被“平人出口”解释成健康。
2. **采集方式与事实不符**：静态照片被要求完成毫米测量、触诊、动态动作和语言功能判断。
3. **规则各自维护**：记录路径、评分词、prompt、UI 选项、术语解释和红线探测分散，已经反复漂移。
4. **派生结果不失效**：观察值修正或补充后，旧辨证报告和结构化结论仍可原样展示。

### 1.3 是否应重新设计底层模型

**证据充足，建议做一次有边界的底层重构；不建议推倒重写整个项目。**

保留 `DailyRecord` 的旧格式适配层，重建三个内核：

- **观察内核**：事实是什么、如何采集、来源是否可靠、是否真正观察过；
- **评估内核**：已知正常、已知异常、未知分别是多少，不把未知算正常；
- **预警内核**：单项筛查提示与组合危重证分开，未评估不等于未触发。

同时给报告、评分和趋势增加输入哈希与规则版本，使派生结果可失效、可复现。

## 3. 底层模型的关键问题

### M1. “0 分”同时表示正常、未识别和无足够信息

`src/scoring.py:440-448` 对未命中词表返回 0；正常基线也为 0。随后：

- 详情与趋势把 0 当正常；
- 模板的平人出口把“已覆盖维度全 0”解释成“未见明显病证”；
- HIGH 分支还要求报告写“健康状态良好，无需服药”（`templates/adaptive_analysis_prompt.md:168-171`）。

这不仅是文案过界，而是推理不成立：

- 教材 PDF p100 明确写淡红舌可见于健康人，也可见于外感表证初起和内伤杂病；
- PDF p111 明确写白苔可为正常，也主表证、寒证；
- 未覆盖、无法判读、模型措辞落出词表，都不含“正常”的证据。

**结论：高优先级的领域 bug。** 应把评分返回改为带状态的 `ScoreResult`：

- `normal`：识别到明确正常值或明确否定；
- `abnormal`：命中异常规则，有分值；
- `unknown`：未命中、无法判读、采集方式不足；
- `not_applicable`：该指标不适用。

`unknown` 不参与“全 0”判断，不参与总分平均，也不允许触发“健康/平人”结论。平人文案最多改为“本次已采集项目未见已知异常”，并同时列出未覆盖和未知项。

### M2. 覆盖度不是诊断置信度，更不能单独授权具体剂量

`src/confidence.py:32-60` 当前仅按 1/2-3/4-6 个维度分为 LOW/MEDIUM/HIGH，并允许 HIGH 输出具体剂量。

它实际测量的是**拍照维度覆盖数量**，不包含：

- 图像是否清晰、是否有比例尺；
- 视觉模型是否经过标定；
- 关键指标是否未知；
- 问诊、既往史、病程、用药、脉诊和触诊是否具备；
- 各证据是否互相矛盾。

教材 PDF p43 明确“望、闻、问、切……不能互相取代”；PDF p118-119 对危重舌象也要求四诊合参。现有 prompt 虽声明 HIGH 不等于四诊合参，但 `allows_dosage(HIGH)` 仍把覆盖数直接转成输出权限，两个口径存在张力。

**建议**：

1. 改名为 `EvidenceCoverageTier` 或 `EvidenceTier`，旧接口保留适配；
2. 另设 `quality_flags` 和 `unknown_count`，不把覆盖数量称为准确率；
3. 覆盖层级只控制报告详细程度；
4. 方剂与具体剂量权限由独立安全策略决定，不能仅由 `covered >= 4` 推导。是否彻底取消该自动授权，列为医学治理裁决。

### M3. 观察状态缺少必要类型

当前用特殊字符串“未拍摄（用户声明正常）”充当观察值，导致：

- 占位可抵消同维度真实观察；
- 占位与真实正常难以在类型层区分；
- 手动/视觉/问诊来源只能在维度清单里粗略表示；
- `not_triggered` 往往只表示“文本没命中”，并未真正排除。

建议至少区分：

- `Observation`：真实获得的观察，含 `value/status/source/method/raw/certainty`；
- `Declaration`：用户声明正常、拒绝、跳过、无法拍摄，不伪装成 Observation；
- `unknown`：采集了但无法解释；
- `not_applicable`：该指标不适用；
- `not_observed`：没有采集。

正常观察、明确否定、用户声明和未观察必须能在 JSON 中独立表达。

### M4. 采集通道超出静态照片能力

以下问题已有原文明证，不应再通过 prompt 要求模型“硬答”：

| 当前字段/行为 | 原著证据 | 结论 |
|---|---|---|
| 舌下络脉 `<2mm` / `>2mm` | PDF p113 的教材标准为不超过 2.7mm、色暗红 | 当前基线与教材不同；且无比例尺照片不能测绝对毫米。需分离“原著基线”和“模型抗过判阈值” |
| 鼻翼煽动评分 | PDF p73 定义为呼吸急促时扇动 | 静态正面照不能确认动态过程；改视频或问诊。肺气衰竭还需重病、喘、额汗等组合 |
| 舌体动态、舌强语謇 | PDF p105、p118 要求转动/屈伸及语言表现 | 静态照片不能完成；改视频或自陈，语言謇涩必须另问 |
| 皮肤“凹陷”水肿 | PDF p227 明确“按之凹陷，不能即起” | 属按诊，不应由视觉模型直接产出；改人工触诊/自陈 |
| 苔滑、苔糙等 | PDF p108 含“扪之湿滑/糙手” | 可记录视觉线索，但不能伪装成已完成触诊；需 method 和不确定性 |
| 黄汗 | PDF p150-151 定义为汗出沾衣、色如黄柏汁 | 应主要由问诊或衣物照片获取，而非普通皮肤照 |
| 下睑结膜颜色 | 当前眼部指引仅要求平视和白睛清晰 | 未撑开下睑时不得默认该指标已覆盖；补专门拍摄/自陈指引 |
| 面红如妆“游移不定” | PDF p58 还有久病、重病及动态语境 | 单张照片最多作筛查线索，不能直接完成戴阳证判定 |

这与已经正确退出评分层的 `palm_temp`、`prickles`、`body_dynamics` 是同一原则，应统一执行，而不是逐字段临时补救。

### M5. 当前指标轴混合了不同观察维度

教材 PDF p107-112 将厚薄、润燥、腻腐、剥落、偏全、真假苔、苔色分开。当前 `coating_thickness` 却同时包含：

- 薄黄：厚度＋颜色；
- 白厚/黄厚：颜色＋厚度；
- 厚腻：厚度＋质地；
- 焦黑：颜色＋润燥；
- 无苔：苔量/剥落/胃气状态，不能简单等同“厚度 8”。

`coating_greasy` 又混合腻、腐和厚腻；`coating_distribution` 放入“苔少”，也不属于分布。

**建议将复合描述解析成独立事实**，例如“黄厚而干”至少写入 `color=yellow`、`thickness=thick`、`moisture=dry`，不要把整句只塞进一个评分轴。

同理，舌质五档合并虽然降低了视觉模型色分难度，但教材 PDF p101 明确区分：

- 淡紫而湿润：阴寒、阳虚语境；
- 紫红/绛紫而干枯少津：热毒、营阴受损语境。

当前把青紫/淡紫并入“紫暗”，而紫红/绛紫又没有规范落点：前者会混淆寒热，后者会落入未识别，都不能支撑完整辨证。**不建议简单恢复旧九档，而应保留原始颜色、润燥和其他证据；无法分辨时标 unknown，而不是伪造确定性。**

### M6. 红线把“单项筛查”和“组合危重证”混为一层

`DANGER_FLAGS.sign` 写组合，`DANGER_PATTERNS` 却常凭一个词触发：

- 戴阳：面红如妆＋手足厥逆 → 实际只查面红如妆；
- 急性黄疸：巩膜黄染＋皮肤黄如橘皮 → 实际只查黄如橘皮；
- 阳明危重：不识人、循衣摸床、微喘直视等 → 实际只查“直视”；
- `tongue_critical`：紫暗＋焦黑干裂 → 实际只查焦黑。

教材 PDF p112 的原文是“苔焦黑干燥，舌质干裂起刺”为热极津枯，并不要求当前 sign 所写的“紫暗”。因此 `tongue_critical` 既不是教材原条，也没有按自己的组合执行。

建议拆成：

- `ScreeningAlert`：单项不特异但值得复核，明确写“因某单项触发复核”；
- `CriticalRule`：所有必需条件满足才成立；
- `unknown`：关键条件未采集，不得写成已排除；
- `not_triggered`：只有在足够证据下明确未满足，不能与未知混用。

急性黄疸中的“橘皮色”也不能单独推出急重症：PDF p56 说黄疸患者黄而鲜明如橘皮可为善色，p58/p88 又以“面目一身俱黄”定义黄疸、阳黄。应评估组合和语境，而不是只调低或调高一个词的分值。

### M7. 派生报告没有输入版本，趋势也缺规则版本

当前报告只记录生成时间和 prompt 模板版本（`web/trends_store.py:307-320`），没有记录：

- 使用了哪一份观察与问诊输入；
- 使用了哪一版评分/映射规则；
- 修正后是否仍然有效。

修正后旧报告继续保留已经实复；补充观察的路径同样没有失效机制。评分规则变化还会使同一历史记录在不同时期得到不同趋势值，现有 `version` 不能替代 `scoring_ruleset_version`。

建议所有派生物携带：

- `input_hash`：规范化观察＋问诊＋上下文；
- `ruleset_version`；
- `generator_version`；
- `created_at` 与 `stale_reason`。

输入改变后，旧报告可保留作历史，但必须标记 stale，不能冒充当前结论。

### M8. 指标定义多处复制，漂移是必然结果

同一指标分别出现在：

- `src/record.py` 的 A/B/C 路径；
- `src/scoring.py` 的词表；
- `scripts/vision_client.py` 的 prompt；
- `web/records_store.py` 的选项、标签和全局 GLOSSARY；
- `web/wizard_store.py` 的识图映射；
- `src/danger.py` 的探测词；
- prompt 和台账。

已经出现：戴阳枚举不召回、舌苔润燥无封闭枚举、15/16/17 问诊分母并存、`明显` 被黄汗释义污染鼻翼煽动、`红赤` 跨部位共用解释、焦黑挂错轴等。

应建立唯一 `IndicatorRegistry`，由它生成 prompt 选项、修正选项、校验元数据和字段级解释。红线规则独立定义，但与注册表做契约测试。

### M9. 总分与跨维度求和没有原著依据

舌诊取最重单项，其他维度取各项指标之和并封顶 10，首页再把六维分数求和。原著没有证明这些不同指标可以放在同一个线性严重度尺上。

眼部已出现实际反例：`黄染 + 黄染轻度` 和 `黄染 + 黄染明显` 都因重复体征累计而成 10 分，轻重无法区分（`src/scoring.py:289-291`）。

建议：

- 先合并同一临床概念，再考虑聚合；
- 趋势以具体指标和具体证据为主；
- 总分若保留，只能明确标为“未经验证的界面启发式指标”，不能等同疾病严重度或用于治疗决策；
- 更稳妥的是取消临床总分，只展示分维度异常与未知情况。

### M10. 病史与采集上下文不足，正常变异容易被误当异常

教材明确给出以下影响因素：

- PDF p97：食物、药物、吸烟可染苔；口腔情况和伸舌姿势也会改变舌象；
- PDF p98：年龄、经期、体质、地域、季节可造成生理变异；先天性裂纹、齿痕、地图苔可无病理意义；
- PDF p71：睡眠欠佳也可见目眶发黑；
- PDF p141-143：主诉、现病史、既往史、个人生活史是问诊基本内容；
- PDF p149：问汗还应了解近期是否服用发汗药物；
- PDF p145 的《十问歌》还包括旧病、病因和服药。

当前 17 项更像“当日症状核对表”，缺少最小上下文。建议优先增加：**年龄段、主诉与病程、近期饮食/染苔因素、当前用药与发汗药、相关既往史/过敏史、睡眠及是否已知先天体征**。不必一开始采集全部病历，更不能因追求完整而延误危险处置。

## 5. 《经方探源》对照结论

完整证据见专项附录，这里只列影响底层设计的结论。

### 5.1 框架主体可以保留

三观口诀、四证总纲、六病要素、基础/复合病机、手足温凉、二便、戴阳/少阴、狐惑、阳明危重、煎服法等，在当前固定文本中均能找到明确出处。模板 `L3948/L3956/L3964` 本次实际仍分别指向表里观、正邪观、津液观，并未失效。

因此，不需要推倒“三观→四证→六病”的主框架；需要修的是输入事实、组合条件、证据状态和输出边界。

### 5.2 需要调整的红线与问诊口径

- **戴阳**：原著明确，当前“红如妆”不触发是工程 bug；但是否单征触发或组合触发，应作为筛查/确证两层处理。
- **狐惑**：主文是“声喝”，另有“一作嗄”；只探测病名会漏掉体征描述。可扩词，但须避免“需与狐惑鉴别”这种提及性误报。
- **阳明危重**：L2822-2826 是组合语境，裸“直视”过于宽泛，且教材 PDF p72 也允许其他病因。
- **脱阳/绝汗**：教材 PDF p150 要求病危背景，并以冷汗、肢冷、脉微或汗热而黏等区分亡阳/亡阴；《经方探源》L8329/L8833 自身也有“冷汗如油”。当前“绝汗(大汗淋漓如油)→脱阳”缺少必要鉴别，应先使用中性危重提示，再补冷热和全身状态。
- **手足温凉**：原著支持重要鉴别价值，但不支持把任何厥冷都机械等同病在阴。教材 PDF p227 有“身灼热而手足厥冷”的真热假寒例。hint 应改“可见于……需结合……”，不要写绝对等号。
- **问诊计数**：实际为 16 项骨架＋手足温凉＝17；模板多处仍为 15，必须统一。
- **食欲**：原著作“饥而不欲食”，当前压缩选项可保留，但六病归属不能由 LLM 自行套用，需医学签认。

### 5.3 出处台账必须重建

当前 `VOCAB_PROVENANCE` 多处“新版行号”仍指向无关段落，例如：

- 唇甲暗黄/淡白：台账 L5565，当前实际为 L7228；
- 下睑淡白：台账 L2763，当前实际为 L3595；
- 苍白/大肉已脱：台账 L2769，当前实际为 L3603；
- 大黄䗪虫丸：台账 L11650，当前实际为 L14839。

上一版审计中的多条行号也无法复现。建议不再把行号当作稳定 ID，而采用：

`source_id + source_sha256 + keyword + PDF页/抽取行号 + 短引文`。

行号只用于当前固定版本的定位，关键词和哈希用于防止再次漂移。

|---|---|
| 继续补词、补分值、补盾牌词 | 短期可修少量召回，但无法表达 unknown、来源、采集方式、组合条件和报告失效，漂移会继续 |
| 全面推倒为复杂事件溯源/新框架 | 表达力强但迁移成本高，不符合本地单用户、标准库和渐进维护目标 |
| **保留适配层，重构观察/评估/预警内核** | **推荐**。能解决根因，又可逐阶段保留现有页面、记录和测试 |

### 7.2 领域对象

```text
Observation
  indicator_id, value, status
  source: vision | manual | self_report | clinician
  method: photo | video | palpation | inquiry | measurement
  raw_text, certainty, evidence_refs

Declaration
  kind: declared_normal | skipped | refused | unavailable
  dimension/part, reason

ScoreResult
  state: normal | abnormal | unknown | not_applicable
  value: number | null
  matched_terms, ruleset_version

AlertEvaluation
  kind: screening | critical_rule
  state: triggered | not_triggered | unknown
  matched_clauses, missing_clauses, evidence_refs

DerivedArtifact
  kind: score | local_overview | llm_report | trend
  input_hash, ruleset_version, generator_version
  created_at, stale_reason
```

关键纪律：

- 声明正常不再是观察值；
- unknown 永远不等于 normal；
- `not_triggered` 不再承担“未评估”；
- 评分、预警、报告是三件不同的事；
- 任何派生物都能判断自己是否过期。

### 7.3 模块划分（保持标准库）

- `src/record.py`：继续作为形状 A/B/C → 统一记录模型的 **Adapter**，不让调用方理解旧格式。
- `src/indicators.py`：唯一指标注册表，持有维度、路径、值域、允许的采集方式、字段级释义、出处和复核要求。
- `src/observations.py`：观察状态、声明、来源与规范化；隐藏状态组合逻辑。
- `src/assessment.py`：评分与证据层级，返回结构化结果；现有 `score()` 暂作兼容 wrapper。
- `src/alerts.py`：筛查规则与组合规则，返回三态结果；现有 `detect_danger()` 暂作兼容 wrapper。
- `src/derived.py`：输入哈希、规则版本和失效判断。
- `src/confidence.py`：逐步改名/适配为证据覆盖层级，不再把数量包装成医学准确率。

这些模块的 **Interface** 应只暴露少量领域操作，调用方不应再直接操作私有路径表、正则或各种占位字符串。

### 7.4 指标注册表是重构的杠杆点

每个指标至少声明：

```text
id / dimension / A、B、C 路径
canonical values + aliases
allowed methods / allowed sources
normal semantics / unknown semantics
field-specific glossary
review policy
source references（source_id + hash + keyword + locator）
scoring rule（可空，且标 heuristic 或 source-backed）
alert links（可空）
```

由注册表生成：

- 视觉 prompt 的字段与封闭枚举；
- 手动录入选项和字段级解释；
- validator 的元数据；
- 记录路径适配；
- 测试用的枚举－评分－预警契约。

这样可以一次消除多类漂移，而不是修一个戴阳再等下一个词出错。

### 7.5 渐进 JSON 迁移

不建议一次性破坏形状 B。可先增加旁路元数据：

```json
{
  "schema_version": 2,
  "observations": { "tongue": { "body": { "color": "淡红" } } },
  "observation_meta": {
    "tongue.body.color": {
      "status": "observed",
      "source": "vision",
      "method": "photo",
      "certainty": "uncertain"
    }
  },
  "declarations": [],
  "derived_meta": {
    "ruleset_version": "2026-10-26.1",
    "input_hash": "..."
  }
}
```

旧形状 B 读取时缺省为历史数据，不能假装知道其采集质量；新写入逐步补齐。A/C 继续只读兼容，新增内容以 B v2 写入。

## 8. 建议实施顺序与验收标准

### 阶段 0：先保护数据和堵安全洞

- 修 `/demo` 覆盖、A/C 红线、共享临时文件、温度/超时失效、危险确认白名单；
- 原子写记录与 `.env`，非法/null 输入统一 400；
- 为上述每一项先加能复现原 bug 的测试。

**验收**：本报告第 2 节所有高优先案例均旧失败、新通过；全量测试保持绿色。

### 阶段 1：纠正“未知＝正常”和派生失效

- 引入 `ScoreResult` 和 unknown；
- 平人出口改为“本次已采集项未见已知异常”，处理零覆盖与问诊阳性；
- 报告写入 input hash，修正/补充后旧报告标记 stale；
- 合并眼部黄染重复概念，修声明正常与真实观察并存。

**验收**：未命中词不再显示正常 0；一张正常照片＋阳性问诊不能进入健康出口；修正后旧报告不会冒充当前报告。

### 阶段 2：统一预警与指标注册表

- 共享否定模块；危险规则分筛查/组合、三态输出；
- 建立 IndicatorRegistry，生成 prompt、UI、校验和契约测试；
- 将黄染、卧蚕等重复概念归一。

**验收**：所有封闭枚举都能说明“如何评分、是否预警、何处解释”；`not_triggered` 不再包含未评估项。

### 阶段 3：调整采集通道和复合指标

- 动态、触诊、毫米测量、自陈分别建模；
- 拆舌苔复合轴、腻/腐、苔量与分布；
- 补下睑拍摄指引、最小病史和染苔/用药上下文；
- 舌质颜色保留 raw 与不确定性，不强行恢复旧九档。

**验收**：静态照片不再产出其无法获得的事实；复合描述能分轴往返；未暴露下睑不会被写成已覆盖。

### 阶段 4：医学治理与趋势口径

- 主人/医学人员逐项签认分值、舌下基线、绝汗分类、出方权限；
- 决定是否取消临床总分及 `covered >= 4 → 可给剂量`；
- 趋势记录规则版本，必要时提供按旧规则复现与按新规则重算两种视图。

**验收**：每项医学变更都有出处、签认和迁移说明；不把未签认的新权重混进工程修复。

## 9. 必须新增的测试层

1. **状态矩阵测试**：正常、明确否定、声明正常、未观察、未知、不适用、真实观察与声明并存。
2. **指标契约测试**：注册表 ↔ prompt ↔ 手动选项 ↔ 评分 ↔ 预警 ↔ 字段级释义。
3. **否定与文本边界**：前后否定、跨逗号/分号、无标点转折、“排除”、提及鉴别、镜面反光等非医学语境。
4. **组合规则测试**：必需条件满足、明确不满足、部分未知；禁止把 unknown 当 not_triggered。
5. **来源能力测试**：静态照片不能写入触诊/动态/绝对测量结果。
6. **派生失效测试**：观察、问诊、规则、模板任一变化均能使相应派生物失效。
7. **数据可靠性测试**：非空库 demo、形状 A/B/C、null、错误日期、共享并发、写回冲突。
8. **原著锚点测试**：关键词必须存在于固定来源；行号/页码只在固定哈希下校验，不把行号当永久 ID。

## 10. 未能验证与不应过度解读之处

- 未调用真实视觉或辨证模型，未验证真实照片准确率、幻觉率及端点兼容性；这些必须另做标定，不能由单元测试替代。
- 未读取真实健康档案，因此某些历史格式问题只证明“可达”，不证明当前档案一定存在。
- Embedding 模型已安装但加载失败时的降级路径只做了代码推断，需 mock 实测后才能定 bug。
- 并发验证证明了进程内竞争；多进程部署、断电和文件系统故障仍需专门测试。
- 原著可证明概念、组合和采集边界，**不能证明任何 0-10 数值权重是医学真值**。所有数值调整仍需独立签认和真实数据标定。
- 本报告不构成医疗诊断或处方建议。

## 11. 最终建议

先做阶段 0 的无争议工程修复，再实施“unknown 状态＋派生失效＋指标注册表”三个结构性改造。它们能以最小迁移成本解决大部分反复出现的问题。

**不建议**直接按上一版审计批量补重证词、统一加分或恢复旧舌色九档。那会把尚未签认的医学假设继续固化到一个尚未分清观察、未知和派生结论的模型里。

当前最合理的产品定位仍是：**本地望诊记录、结构化整理、复核提示和趋势辅助工具**。在采集质量、未知状态和四诊信息未被显式表达之前，不应把“覆盖四维”或“全 0 分”解释为医学上的高置信健康/可出具体剂量结论。
