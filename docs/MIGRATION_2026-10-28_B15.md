# B15 红线裁决生命周期（v1.13.8）

**日期**：2026-10-28
**范围**：G21–G26。按既定默认语义实现，不重新划分医学红线，不改变预警规则、权重、分值或剂量策略。

## 1. 状态与接口

```text
自动触发/外部标记
       ↓ refresh_danger
证据未变的 keep / dismiss ──→ 不重复弹层
       ↓ 新证据或待确认
review_snapshot → danger_token → 逐项 keep / dismiss → 写入审计
       ↓ 证据消失
自动撤销触发 + clear 审计（可再次复核，不伪造医学观察）
```

核心接口位于 `src/danger_review.py`：

- `refresh_danger(raw, previous_raw=None, source=..., client=...)`：重算自动触发，保留无自动证据的外部标记，恢复证据匹配的既有裁决。
- `review_snapshot(raw)`：返回当前触发、待确认键、证据、已保留键和令牌。
- `apply_decision(...)`：校验令牌及完整逐键裁决后写 `danger_review`。
- `merge_scope(...)`：限制 merge 只能判本轮触及维度或问诊证据为误报。

`refresh_danger` 在修改红旗前拒绝 A/B 混合结构，不借刷新把非法结构洗成合法记录。已完成的 `clear` 不随后续刷新重复追加。

## 2. `danger_review` 审计

每个裁决按键追加一条，字段包括：

- `key`、`decision`：`keep` / `dismiss` / `clear`；
- `original_triggered`：本次展示时的触发集合；
- `evidence`：命中证据的路径与文本；
- `evidence_hash`：该键证据的 SHA-256；
- `source`、`client`、`at`：向导、观察修正、问诊或上下文来源，请求来源和时间。

`dismiss` 写入 `danger_flags.dismissed`，**不写入 `not_triggered`**。原始观察、问诊和人工历史不互相伪造。`clear` 是证据消失后的自动撤销，不是用户手工把红旗改成正常。

validator 校验审计列表、逐键决定、原触发集合、证据、哈希、来源和时间；旧记录没有审计字段仍可读取，首次需要复核时再建立。

## 3. 确认令牌与旧客户端

`danger_token` 绑定当前触发键及对应证据。服务端只在展示待确认项后签发，首次提交就带 `keep`、`fix` 或逐键 `dismiss` 而没有令牌，返回 **409** 和新的复核数据，不落盘。

- 推荐请求：`{acknowledge: {key: "keep"|"dismiss"}, danger_token: "..."}`。
- 兼容旧值 `acknowledge="keep"` 或 `"fix"`，但仍必须回传本次令牌；`fix` 按本次待确认项的误报处理，不再清空为 `not_triggered`。
- 证据或待确认集合改变后，旧令牌返回 409；必须按新证据重新确认。
- 每次必须裁决本次展示的全部待确认键；缺键、非法值或非法令牌均不能放行。

## 4. merge、修正与问诊

- 已 `keep` 且证据未变的旧红线不再弹层；只有当前待确认项进入复核列表。
- merge 可以保留未触及的旧项，但不能把它们判为误报；误报只接受本轮触及的观察维度或问诊证据。
- 修正观察后重算自动项。证据消失记录 `clear`；无关字段修正不会使既有误报复活。新证据需要新的确认，不沿用旧裁决。
- 问诊和上下文更新使用同一刷新逻辑，改答可以撤销相应红线，并留下 `source=inquiry/context` 的审计。
- 无自动证据的外部/人工标记继续保留，不因无法重算来源而被静默清除。

裁决历史纳入报告输入指纹；改判后旧报告会按既有机制标为过期。详情页将误报单独显示为“原始观察与审计保留”，不显示绿色“均未触发”；辨证输入也明确列出误报语义。真实观察不再被同维度其他部位的“声明正常”遮蔽。

## 5. 界面

- 使用原生 `<dialog>` 和 `showModal()`，提供对话框标题、焦点约束与 Esc 退出。
- 默认每项为 `keep`；可以逐项选择 `dismiss`，提交时回传令牌及完整决定。
- “返回修改观察/问诊”只关闭弹层，不写记录，不以“去修正”为名清旗。
- merge 中不可判误报的旧项显示限制原因；错误/证据变化文本以安全文本节点展示。
