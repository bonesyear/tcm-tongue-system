# B13 医学执行闸门（v1.13.7）

**日期**：2026-10-28
**范围**：F2、F3、F4、F5、F21、F28。只把已有置信度和安全结构约束变成可执行代码；不改变医学权重、红线分类、评分或剂量策略，不把结构校验当作医学批准。

## 1. 方剂材料的统一读取

新增 `DailyRecord.get_formula_material()`，供安全检查汇总：

- `formula`、`formula_adjust`、`formula_with_dosage`，空值不遮蔽其他候选；
- `diagnosis` / `deepseek_diagnosis` 的 `方剂建议`，新旧容器独立检查；
- 上述诊断容器的 `report.markdown`，只截取标题为“方剂建议”或“剂量建议”的 Markdown 段落，避免把全文的鉴别讨论一刀切当成处方。

原有 `get_formula()` 的返回形状不变。新安全校验使用汇总接口，避免首个空容器让真实方剂消失。

`has_formula_content()` 补充“方名／方剂／组成／药物／处方／prescription／composition”等键，以及通用“汤／散／丸／饮”方名形态。剂量识别由 `has_dosage_content()` 共用，支持：

- 阿拉伯数字、全角数字/字母和中文数字；
- `g`、克、两、钱、枚、升等既有经方单位。

识别时只在独立文本副本上做 NFKC，不改写记录原文。方向标题如“方剂类别方向”不属于方剂/剂量建议段落；LOW 的鉴别方向、MEDIUM 的类别方向不因“汤”字出现在无关讨论中就被拦截。

## 2. 置信度闸门进入实际调用

`scripts/input_validator.py` 继续按自报与覆盖推断中较严格的等级执行：

- 任一为 LOW 时，新增具体方剂材料是 error；
- 任一无剂量权限时，新增具体剂量是 error，实际调用 `allows_dosage()`；
- LOW 禁方剂与非 HIGH 禁剂量分别报告，不能靠省略或乱填 confidence 绕过。

报告写回复用同一个 validator，不再另写一套只检查阿拉伯数字加“克”的判断。修正、报告生成和向导提交都把返回的 **全部 errors** 视为阻断项，不再按 `❌` 或其他 emoji 前缀丢弃 `🚨` 安全错误。CLI 的 errors/warnings 输出契约保留。

## 3. 原记录与候选的比较

`records_store.validate_candidate(raw, workdir, previous_raw=None)` 增加可选原记录参数：

- 无原记录时，所有校验错误均阻断；
- 有原记录时，在原记录和候选中都存在的同一校验错误转为 `⚠️ 存量校验问题`，允许修正其他字段；
- 本次新增的错误一律阻断，包括覆盖下降后新形成的 LOW＋具体方剂；
- 新合规内容移除旧违规后，不再产生“当前存量违规”告警。

修正流和报告流在修改前保存原记录快照；向导 merge 使用读取时的旧记录。校验通过后仍沿用备份、文件版本和原子写入，不因闸门绕过并发保护。

## 4. 红旗结构与探测异常

- `get_triggered_danger_flags()` 对 B 式 `triggered` 列表和 A 式旗对象取并集，保持列表顺序并去重。
- validator 拒绝同一 `danger_flags` 中混用两种旗形；读取并集不能代替结构校验。
- 三态列表元素必须为非空字符串，非法元素不能静默变成已触发或未触发。
- 红线探测异常转为明确 warning，保留校验主流程，但不再 `except: pass` 静默吞错。

本批不处理 B15 的人工 keep/dismiss/clear 生命周期、证据哈希或旧裁决恢复语义。

## 5. 验证与未覆盖范围

- 回归同时覆盖：LOW 鉴别方向可写、MEDIUM 类别方向可写、存量违规可改其他字段、降级形成的新违规不写盘、合规报告可移除旧违规。
