# B28 受管统一视图与并发恢复（v1.20.18）

**日期**：2026-11-04
**范围**：消除分类根统一视图的重复复制与 RAG 重建，补齐全量并发、发布失败、缓存损坏和进程强退恢复。保留 B26/B27 的候选一致性与类别闸门，不修改源知识库、导入 ZIP 或医学规则。

## 1. 内容版本与复用

`web/kb_view.py` 负责统一视图生命周期，`kb_evidence.py` 只负责候选检索。缓存键包含类别、规范化根、相对文件路径、Markdown 正文和根别名词典的内容 SHA-256，不只依赖文件大小或 mtime；同尺寸、同时间戳的内容变化也会生成新版本。

同版本命中后复用已发布目录、类别清单、内存别名及现有文件/RAG 缓存。每次调用仍读取源文件计算内容版本，因此缓存不是无需源库的离线副本，也不承诺与三类直接共用同一综合根同样快。

## 2. 构建、发布与损坏恢复

- 缓存根写锁覆盖构建与发布，同版本线程和进程不重复复制；实际检索在锁外进行。
- 文件先写入可识别暂存目录，复制后再次计算源内容版本，变化则拒绝发布。清单完整后通过同卷 `os.replace` 原子发布。
- 清单保存类别归属与合并别名，不包含源根明文路径。清单或文件集合损坏时自动重建；复制失败不留下已发布半成品。
- 默认保留 8 个近期视图。超出容量先失效本进程对应缓存，目录经过 1 小时保护期才删除，避免撤掉并发读者正在使用的文件。

## 3. 崩溃清理与源库保护

缓存位于 `<TCM_DATA_ROOT>/cache/kb-unified/`，属于可删除重建的派生数据，已加入 Git 忽略，不是新的知识库来源或部署前置。

进程强退无法当场执行清理；下次缓存操作或服务启动会在写锁内清理系统标记目录中匹配约定名称的暂存目录，不触碰无关文件、源库或 ZIP。已完整发布的视图可以复用。

如果缓存目录与任一源根重叠，系统不创建锁或缓存，而回退到一次性临时视图，并在退出时清理其缓存，避免修改源库或递归收录缓存。

## 4. Windows 锁竞态修复

真实双进程验收发现：两个进程同时打开空 `.write.lock` 时，一个已加锁，另一个仍写入初始化字节，触发 `PermissionError`。Windows 已验证可直接锁定空文件，因此删除初始化写入，锁与解锁统一使用第 0 字节。该修复同时覆盖配置、记录和统一视图共用锁。
