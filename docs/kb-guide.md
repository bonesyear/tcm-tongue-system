# 从中医著作到知识库

本文说明如何将一本中医著作整理为本系统可检索的知识库。AI 可以协助提取文本、归类主题和生成文件；资料是否可用、内容是否符合原意，以及最终是否导入，由使用者核对和决定。

整理流程如下：

> 准备资料 → 确认读取范围 → 编制主题清单 → 分批生成正文 → 对照原书复核 → 打包导入 → 检索验收

文中的目录和文件均为结构示例，不含医学资料。系统只校验文件格式和检索结果，不审核资料的医学质量、授权状态或适用范围。知识库内容不能作为诊断依据。

## 1. 两种导入方式

**个人自建知识库时，只需用 AI 制作一个综合知识库 ZIP，不必再拆成体质、食疗、方剂三个子库或三个 ZIP。** 三类专用包用于确有按类独立提供、更新和重置资料需求的场景，不是个人建库的额外步骤。综合包内的标准目录只用于主题归类，不是三个子库。

设置页的「知识库」卡片先列出默认折叠的「子知识库」分组，展开后可使用三类专用导入；综合知识库直接展示在分组之后。两种入口的清单要求如下：

| 导入方式 | 适用资料 | 清单要求 |
| --- | --- | --- |
| 中医体质辨证专用包 | 体质、体征、辨证资料 | 根目录必须有 `kb.yaml`，`category: constitution` |
| 食疗专用包 | 饮食宜忌、食疗资料 | 根目录必须有 `kb.yaml`，`category: diet` |
| 方剂专用包 | 方剂、方证、煎服资料 | 根目录必须有 `kb.yaml`，`category: formula` |
| 综合知识库 | 一个 ZIP 中包含多类资料 | `kb.yaml` 可省略；提供时使用 `category: composite` |

三类专用包分别导入、更新和重置，适合按类维护资料。综合包适合集中整理一本著作或一组相关资料。本文以综合包为例，说明从原书到导入验收的完整过程；专用包的格式见[自建知识库格式与导入规范](KB_AUTHORING.md)。

未配置专用根时，系统默认从综合库回退检索。开启「严格分类模式」后只使用三类专用根，综合库不参与检索，未配置的类别会隐藏对应信息。

## 2. 综合包的目录结构

在仓库外新建一个工作目录，例如 `my-kb/`。按著作的实际内容使用以下目录：

```text
my-kb/
├── kb.yaml                  # 可选；提供时 category 为 composite
├── diagnostics/             # 体质、体征、辨证资料
│   └── topic.md
├── diet-lifestyle/          # 食疗、饮食宜忌资料
│   └── topic.md
├── formulas/                # 方剂、方证、煎服资料
│   └── topic.md
└── synonym_map.yaml         # 可选；根目录别名词典
```

至少需要一份非空 Markdown。著作没有涉及的类别可以省略，不应为凑齐目录补写内容。能够归类的资料放入对应标准目录；确有跨类且无法确定归属的笔记，可放在 `notes/` 等普通目录，作为通用候选。

`constitution/`、`diet/`、`formula/` 是分类专用副本的保留目录，不能放进综合 ZIP。它们与上表中的综合包目录用途不同，不要混用。

## 3. 整理前的准备

### 3.1 资料和使用边界

确认你有权复制、整理和使用该著作。能够阅读不等于有权复制或再分发；原书、衍生资料和 ZIP 不应提交到公开仓库。如果需要把资料发送给云端 AI，还须另行确认许可和隐私要求。

导入知识库不是训练或微调模型，也不会自动修改指标词表、评分、权重、红线、置信度、方剂或剂量规则。AI 生成的摘要、改写和归类仍可能有误，不能替代原文核对。

### 3.2 文本与页码

优先使用可检索的文字版资料。扫描 PDF 需要先完成 OCR；无法辨认的页面保留原图并作出标记，不要根据上下文猜字。

整理时同时保留章节名和页码。PDF 页码与书页页码不一致的，应同时记录，例如“PDF 第 18 页／书页第 36 页”，便于回查。

### 3.3 工作目录

原资料、核对记录和待导入文件应分开保存：

```text
my-kb-work/
├── source/              # 原书或 OCR 文本，不打包
├── review/              # 主题清单、漏读页、复核记录，不打包
└── my-kb/               # 待导入的综合知识库
    ├── diagnostics/
    ├── diet-lifestyle/
    └── formulas/
```

原书、工作目录和各版本 ZIP 由使用者自行备份。不要把唯一原稿放进系统的导入副本目录。

### 3.4 五项内容覆盖检查

选书或开始整理前，先检查实际读到的内容能覆盖哪些主题。这五项是**覆盖检查**，不是要求一本书必须全部具备，也不是让 AI 补齐缺项的理由。

| 检查项 | 需要从原资料中找到什么 | 建议目录 |
| --- | --- | --- |
| 1. 体质与辨证框架 | 体质、证候、病机等如何分类、关联和判断；不能只有体质名称或孤立方名 | `diagnostics/` |
| 2. 舌诊及其他望诊词表 | 舌质、舌苔、舌下络脉，以及资料实际涉及的头面、目、耳、手、皮肤等观察表述 | `diagnostics/` |
| 3. 方剂、方证与煎服法 | 方剂的适用条件、方证、方义、煎服和禁忌；出处不清的剂量不要补写 | `formulas/` |
| 4. 食疗宜忌 | 饮食适宜与禁忌、四气五味及其适用条件和限制 | `diet-lifestyle/` |
| 5. 九种体质分类标准 | 九种体质的分类名称、判定维度和依据，能够回查明确的标准或资料来源 | `diagnostics/` |

第一项是辨证框架，第五项是体质分类依据，两者不能互相替代。望诊词表进入的是检索语料，不会因为是书面表述就自动成为系统的封闭评分词；导入资料也不会改变既有评分、权重或剂量规则。

缺少某项不代表不能建库。可以只整理实际覆盖的内容，不为凑齐目录而补写；系统会按实际可用来源和启停状态展示相应信息，缺失或检索无命中的内容不应由模型编造。

### 3.5 参考资料的地位与运用

本项目的既有知识整理中，不同资料承担不同作用，不应把书名、出处和医学体系混为一谈：

- **《中医诊断学》**：主要用于舌诊知识、舌象词汇及部分现代望诊基线。它不是九种体质分类的来源，也不能替代方剂、方证或食疗资料。
- **中华中医药学会《中医体质分类与判定》（ZYYXH/T157-2009）**：用于九种体质的分类名称与判定框架。这是行业标准，不是普通著作，也不应与其他辨证体系混为一谈。
- **其他方剂、经方著作**：可作为方证、治法、煎服法和部分饮食禁忌的来源。具体能覆盖哪些主题，必须以实际读取的章节、条文和出处为准，不能仅凭书名推定。

同一主题使用多种资料时，应分别记录书名、版本、章节和页码；原文、摘要与 AI 自行说明仍需区分。资料的地位不等于医学有效性已经获得独立验证。

### 3.6 一两本书实际能做成什么

一两本书如果实际覆盖了上述主题，就可以整理出结构类似、能够导入并参与检索的综合知识库；如果只覆盖部分主题，就只制作相应内容。例如诊断教材与方剂资料可能支持望诊词汇、辨证和方剂候选，但食疗部分仍可能缺失。

目标是生成**同格式、可对接、来源可追溯**的资料，不是复刻某个既有本地库。不同书籍、版本、整理范围和别名词典会产生不同候选与报告输入，不能承诺内容覆盖、命中数量或模型输出完全一致。格式校验通过也不构成医学背书。

开始整理前，可让 AI 先按这五项逐项报告“已覆盖／部分覆盖／未覆盖”、对应章节页码及证据，再决定主题清单；不要直接接受整本书生成的 ZIP。

## 4. 让 AI 分批整理资料

能读取本地文件并写入指定目录的 AI 助手，可以执行下面的完整任务。使用普通聊天 AI 时，也可按同样顺序分段提供章节，再手动保存生成的文件。没有文件写入能力的 AI 输出代码块，并不等于已经生成本地文件。

将方括号内容替换为实际路径，在项目根目录提交以下任务：

```text
任务：只依据我指定的中医著作，整理一个可导入本系统的综合知识库 ZIP。

项目根目录：【本地项目目录】
著作位置：【本地文件、目录或授权 URL】
输出目录：【仓库外的 my-kb 目录】
核对记录目录：【仓库外的 review 目录】

先阅读 docs/KB_AUTHORING.md，按项目当前的格式要求执行。
只读取我明确提供的资料，不使用其他知识库，不从记忆补充著作中没有的内容。

第一步：核对资料，暂不生成正文或 ZIP。
1. 列出实际打开的文件、章节和页码范围，说明是文字版还是扫描件。
2. 列出无法打开、无法辨认、页码不确定或尚未读取的部分。
3. 按本文 3.4 的五项覆盖检查，逐项报告“已覆盖／部分覆盖／未覆盖”，
   附对应章节、页码和证据；缺项不得从记忆或其他知识库补齐。
4. 根据实际读到的内容编制“主题—出处”清单，字段包括：
   主题、建议文件路径、来源章节与页码、内容性质（原文节选／忠实摘要／自行说明）、
   适用条件与限制、未处理内容。
5. 文件路径按实际内容使用 diagnostics/、diet-lifestyle/、formulas/；
   著作未涉及的类别不要补写，无法归类的笔记单独标明。
完成本步后暂停，等待我回复“清单已确认”。

第二步：收到“清单已确认”后，按清单分批生成正文。
1. 逐主题生成 UTF-8 Markdown，不要一次跳过未处理的章节。
2. 每份文件写明来源、许可、整理日期和整理说明；小节跨页时继续标明出处。
3. 原文节选、忠实摘要和自行说明分别标注，不把生成内容称为原文。
4. 保留原书的适用条件、限制、歧义和上下文，不改写成无条件结论。
5. 无法辨认、找不到依据或出处不确定的内容写入核对记录，不猜测、不补齐。
6. 将读取范围、主题与文件的对应关系、未处理页面写入 review 目录；
   核对记录不要放进待导入目录。
完成后逐文件报告路径和来源范围，等待我回复“正文已核对”。

第三步：收到“正文已核对”后，生成其余文件并打包。
1. 在根目录生成 kb.yaml：schema_version 为 1，category 为 composite；
   name、source、license 按我提供的信息填写，不添加未知、嵌套或重复字段。
2. 确有必要时，在根目录生成 synonym_map.yaml。别名只连接有明确同义依据的词，
   目标词应在正文中实际存在；不修改评分、红线、权重或剂量规则。
3. 不带入模板占位正文。README.md 只放说明，有效正文使用其他文件名。
4. 检查文件类型、编码、路径、文件数和大小。原书、OCR、核对记录、
   私有配置和无关文件不得打入 ZIP。
5. 不使用 constitution/、diet/、formula/ 这三个保留目录。
6. 将 my-kb 目录的内容打成一个 ZIP，使标准目录和 kb.yaml 位于 ZIP 根目录，
   不要再嵌套一层 my-kb/。
7. 报告 ZIP 路径、完整文件清单、各类来源范围、未处理内容及建议测试的词。

只操作我指定的输出目录和核对记录目录。不要读取或修改真实 .env、健康记录、
照片或其他知识库，不要上传公开仓库，不要提交或推送 Git。
无法确认的内容必须明确报告，不得假装已经读取或核对。
```

如果 AI 未在约定步骤暂停，先不要接受它生成的 ZIP。要求其重新列出实际读取范围和主题清单；无法提供出处的段落不应进入正式知识库。

## 5. 正文格式与原文复核

正文按主题分批整理。每个文件应有明确的主题和可追溯的来源，不要求固定医学章节。推荐格式如下：

```markdown
# 【主题】

来源：【书名、作者、版本、章节、页码】
许可：【你确认的使用许可或授权依据】
整理日期：【YYYY-MM-DD】
整理说明：【原文节选、忠实摘要或自行说明；说明 AI 参与方式】

## 【小节】

【与上述来源对应的正文；必要时在小节末尾补充具体页码】
```

这些元数据用于追溯，不代表系统对内容真实性、医学有效性或授权状态的认证。主题较多时按自然章节合并相关文件；ZIP 最多容纳 32 个文件，不要为减少文件数删去出处或适用条件。

生成正文后，逐篇对照原书检查：

1. 正文是否来自清单标明的章节，节选和摘要是否区分清楚。
2. 节选是否逐字一致，摘要是否准确保留原意。
3. 适用条件、限制、歧义和上下文是否完整。
4. 作者、版本、章节和页码是否能够实际查回。
5. 是否出现原书没有的解释、同义词或确定性结论。
6. 无法读取和未处理的内容是否仍保留在核对记录中。

AI 可以协助列出原文与摘要的差异，但“语义相近”不能直接视为无误。需要修订时，只修改已确认有问题的文件，并重新记录修改位置和依据。完成复核后再进行打包。

## 6. 清单与别名词典

### 6.1 `kb.yaml`

综合 ZIP 可以省略 `kb.yaml`。需要记录资料名称、范围和许可时，在根目录添加：

```yaml
schema_version: 1
category: composite
name: 我的资料
source: 资料范围说明
license: 使用许可或授权依据
```

`schema_version` 固定为 `1`，`category` 固定为 `composite`。`name`、`source`、`license` 可省略，不接受嵌套、重复或未知字段。清单只是使用者填写的声明，不构成医学或许可审核。

### 6.2 `synonym_map.yaml`

只有需要用一个已知同义表达找到正文中的另一个表达时，才添加别名词典：

```yaml
自定义口语:
  - 资料中实际使用的规范词
  - 另一个有明确同义依据的表达
```

原查询词会自动保留，无需在列表中重复。别名只扩展检索，不会成为评分词或医学规则。没有明确同义依据时，不应为了“提高命中率”添加宽泛或相互矛盾的映射。

## 7. 打包与导入

### 7.1 文件检查

| 项目 | 要求 |
| --- | --- |
| ZIP 大小 | 不超过 8 MiB |
| 文件类型 | 仅 `.md`、`.yaml`、`.yml` |
| 文本编码 | UTF-8，允许起始 BOM |
| 文件数 | 最多 32 个文件；ZIP 总条目最多 64 个 |
| 单文件 | 展开后不超过 4 MiB |
| 总展开大小 | 不超过 32 MiB |
| 路径 | 相对 POSIX 路径；不使用绝对路径、`..`、反斜杠、盘符或隐藏路径 |

加密 ZIP、符号链接、特殊文件、重复路径和大小写冲突路径都会被拒绝。任何层级中精确大写的 `README.md` 文件或目录不参与检索，其他大小写可能作为正文；说明和有效正文应分开存放。

打开 ZIP 后应直接看到实际使用的标准目录和可选的根目录清单，不应再嵌套一层 `my-kb/`。完整规则见[自建知识库格式与导入规范](KB_AUTHORING.md)。

### 7.2 生成 ZIP

可以使用系统压缩工具，也可以在综合工作目录的上一级运行：

```bash
python -c "import shutil; shutil.make_archive('my-kb', 'zip', 'my-kb')"
```

将两处 `my-kb` 换成实际目录名。命令会生成 `my-kb.zip`，并把该目录内的内容放在 ZIP 根目录。手工压缩时，只选择待导入的标准目录、`kb.yaml` 和可选的 `synonym_map.yaml`，不要选入 `source/`、`review/`、原书或项目配置。

### 7.3 导入综合知识库

1. 打开「设置 → 知识库」，找到「子知识库」分组之后的「综合知识库」。
2. 确认综合知识库开关已开启，再选择 ZIP，点击「导入综合知识库」。
3. 等待校验完成，确认状态为「知识库可用」，核对可检索 Markdown 数量。
4. 如需当前目录，在「技术详情」中查看；不要直接修改程序管理的导入副本。
5. 展开「子知识库」，检查整组开关已开启，且「严格分类模式」处于关闭状态，否则综合回退不参与检索。

综合开关只控制综合根及分类回退，不影响已配置的独立专用根；整组开关会暂停三个子库及综合回退，但保留各子库自身选择。开关只控制检索、报告和本地速览，不删除文件。

非本机访问需要先验证管理口令。导入只进行本地文件校验，不调用模型。

每次成功导入都会**替换综合导入副本，而不是与旧 ZIP 合并**，并解除综合自身停用。新 ZIP 必须包含希望继续使用的全部综合资料；三类专用副本及其选择会保留，整组状态不变，外部原稿和其他类别不会被移动、覆盖或删除。校验或激活失败时保留旧副本及配置；配置写回失败会按事务规则恢复。

## 8. 导入后的验收

### 8.1 直接检查检索

从已整理的正文中选择确定存在的词，在项目根目录运行：

```bash
python -c "import json; from src.retrieval import retrieve; print(json.dumps(retrieve('资料中确定存在的词', kb_root=r'知识库目录'), ensure_ascii=False, indent=2))"
```

`知识库目录`可在综合知识库的「技术详情」中查看。检查返回的文件、行号和正文；配置过别名词典的，再用词典中的口语键测试一次。

没有命中时，先核对查询词是否确实存在于正文、文件是否位于预期目录、正文是否误放在 `README.md` 中。报告没有采用某段资料，不等于检索失败。

### 8.2 检查报告候选

配置辨证模型后，可生成一份报告并检查候选参考：

- 候选是否来自预期文件，类别归属是否与实际目录一致；
- 模型表述是否保持原意，适用条件和限制是否仍然保留；
- 无命中、缺库或失败是否如实披露，而不是由模型补写。

候选参考不等于模型实际引用，更不等于医学结论成立。报告仍须回查原资料并由人工复核。更换知识库或启停导致有效来源变化后，已有报告会提示过期，需要重新生成；恢复原状态且指纹一致时，可继续显示原报告。

## 9. 后续维护与专用包

### 更新综合包

在自己的工作目录中修改原稿，重新核对、打包并导入。新增 ZIP 不是增量补丁，必须保留仍需使用的全部文件。正文修改后，还应复查别名并复测此前的确定词。

### 使用三类专用包

需要按类提供、更新或重置资料时，展开设置页前方默认折叠的「子知识库」分组，使用三类专用导入。专用 ZIP 根目录必须包含 `kb.yaml`：

```yaml
schema_version: 1
category: constitution
name: 自定义资料名称
source: 来源说明
license: 使用许可或授权依据
```

`category` 按导入卡片分别使用 `constitution`、`diet`、`formula`。专用根中的普通子目录按导入类别处理；每次导入只替换本类副本并解除本类自身停用，不自动开启整组或改变其他子库选择。分类重置只删除对应专用副本并停用该类，不是综合包的重置操作。

只有确定不再使用综合回退时，才开启「严格分类模式」。它独立于整组开关，开启前应分别验证三类专用库；未配置的类别会隐藏对应内容。统一检索缓存由系统管理，无需备份或手工编辑，确需清理时先停止服务。

## 10. 常见问题

| 情况 | 处理方法 |
| --- | --- |
| AI 声称已通读，但给不出章节和页码 | 重新核对实际读取范围，不接受“已通读”的口头结论。 |
| 扫描件生成的文字流畅，却无法与原书对应 | 先改进 OCR；无法辨认处保留标记，不猜字、不补句。 |
| 正文出现原书没有的内容 | 按出处重做或删除，不把模型补写标成原文。 |
| 一本书同时涉及多类资料 | 综合包内按主题使用三个标准目录；无关内容不导入。 |
| 提示清单类别不匹配 | 综合导入使用 `category: composite`；专用导入与对应卡片保持一致。 |
| 导入成功但文件数不符 | 检查有效正文是否误放在 `README.md` 或隐藏路径中。 |
| 再次导入后旧资料消失 | 综合导入采用替换语义；从自行保存的完整工作目录或旧 ZIP 恢复。 |
| 某类报告没有命中 | 检查对应目录是否有相关资料；检索无命中不应由模型补写。 |
| 文件超过数量或大小限制 | 按自然主题合并或精简，保留出处与限制，不绕过校验。 |

## 11. 导入前核对清单

- [ ] 实际读取范围、无法辨认页面和未处理内容均有记录。
- [ ] 五项内容覆盖状态及对应章节页码已确认，未覆盖部分没有由 AI 补写。
- [ ] 主题清单和目录归类已经确认，正文已逐篇对照原书复核。
- [ ] 来源、适用条件和限制可追溯，节选、摘要与自行说明区分清楚。
- [ ] ZIP 根目录和文件格式符合要求；如提供 `kb.yaml`，类别为 `composite`。
- [ ] 严格分类模式已按导入方式正确设置，综合库状态和文件数正常。
- [ ] 确定词和必要的别名测试已验证，报告候选已回查原资料。
- [ ] 原书、工作目录、核对记录和需要保留的 ZIP 已另行备份。
