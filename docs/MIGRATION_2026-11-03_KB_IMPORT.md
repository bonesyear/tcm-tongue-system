# 知识库 ZIP 导入与自建标准迁移（v1.16.0）

**日期**：2026-11-03
**范围**：在 v1.15.0 公私分离基础上，允许 clone 用户导入自己的本地 ZIP 知识库，并开放自建格式与非医学合成模板。每次导入覆盖程序管理的副本，但不得破坏仓库外的原始知识库。

## 1. 原库与导入副本的职责

- 现有外部 `TCM_KB_ROOT` 是用户原库，可以继续手动配置和检索；导入器不会把它作为替换目标，不会移动、覆盖或删除其中的文件。
- 网页导入固定使用 `<TCM_DATA_ROOT>/private_kb/`。该目录由程序管理，每次成功导入完整替换上一份导入副本，不合并 ZIP。用户不得把唯一原稿放在这里。
- 配置可写时，成功导入把 `.env` 的 `TCM_KB_ROOT` 指向导入副本；这会改变生效检索根，但不删除原库。需要回到原库时可手动改回部署配置。
- 环境变量锁定时仍生成/覆盖导入副本，但不写 `.env`，响应为 `configured=false`，环境变量指向的当前根继续生效。

## 2. 校验与替换事务

上传先完整写入同级暂存目录，全部校验成功后才进入替换：

1. 校验 ZIP、路径、文件类型、UTF-8 文本及根目录 `synonym_map.yaml`。
2. 旧导入副本若存在，先移动为 `.kb-backup-<随机串>/`，再把暂存目录激活为 `private_kb/`。
3. 激活失败时恢复旧导入副本。配置写回失败时，把新副本保留为 `.kb-failed-<随机串>/`，恢复旧导入副本并返回错误。
4. 成功后删除旧导入副本备份，并清除该根的词典、文本和 RAG 缓存。原始外部知识库在整个过程中不参与目录替换。

同一 Web 进程内，导入和 `.env` 写回共用写锁。多个服务进程或外部程序同时修改同一数据根不受该锁协调，部署时应避免这种并发；目录两步替换也不宣称对同时到达的检索提供跨进程原子快照。

### 安全限制

- ZIP 不超过 8 MiB；最多 32 个文件、64 个总条目；单文件不超过 4 MiB；总展开不超过 32 MiB；单文件压缩比不超过 200。
- 仅 `.md/.yaml/.yml`，UTF-8/BOM，至少一份非空 Markdown；仅 Stored/Deflated。
- 拒绝绝对路径、穿越、反斜杠/盘符、隐藏路径、重复或大小写冲突路径、符号链接、特殊文件和加密包。
- 普通 Windows ZIP 只有权限位时按普通文件处理；只有明确文件类型为链接、目录以外的特殊类型时才拒绝。
- 端点仅管理员可用，沿用 Host、同源和局域网会话闸门；上传文件名不决定本地目录，不读取真实 `.env`，不调用模型。

## 3. 自建标准与行为边界

`docs/KB_AUTHORING.md` 规定目录、UTF-8、来源/许可元数据建议、受限 YAML 词典、打包、导入、回滚和核对步骤。`templates/kb/` 只含非临床占位内容，未复制私有原文。

用户文献只成为 Grep/RAG 检索语料与可选别名映射；不自动修改医学权重、指标词表、红线分类、评分、置信度、方剂或剂量策略，也不训练/微调模型。结构校验通过不证明许可、内容准确性或医学有效性。未配置知识库时仍按既有行为降级，不伪造引用。

## 4. 检索修复

此前 `retrieve(..., kb_root=...)` 的词典仍可能默认跟随环境变量。现在 OR 与 AND 查询都在调度层按同一 `kb_root` 加载 `synonym_map.yaml`，显式 `syn_map` 仍优先用于测试/调用方注入。

新增 `src.retrieval.invalidate_kb_caches(kb_root)`，只清除指定根的词典、文本和 RAG 缓存。外部手工改库仍需重启或清缓存；网页导入/回滚会自动调用。核心检索仍只用标准库，不新增依赖。
