# 知识库事务、类别契约与缺类写入硬化（v1.18.0）

**日期**：2026-11-03
**范围**：修复全面架构审查发现的综合导入删除分类副本、配置写后失败未完整回滚、类别只看文件存在等问题。原始知识库不做修改。

## 1. 综合导入与配置事务

综合 `composite` 导入仍使用 `<TCM_DATA_ROOT>/private_kb/`，但替换前会把三个分类子目录复制到事务保留区，激活综合副本后原样恢复。综合包本身不得包含 `constitution/`、`diet/`、`formula/` 保留目录，避免与程序管理的分类副本冲突。

分类导入在写配置前记录原值。若写入或写后回读失败：

1. 比较当前配置与原值，必要时恢复原配置；
2. 将新副本移到 `.kb-failed-<随机串>/`；
3. 恢复旧副本和分类子目录；
4. 清理对应检索缓存。

配置回滚也失败时返回明确错误并说明目录状态，不再返回“已恢复”的虚假结果。原始外部库始终不参与替换。

## 2. 分类清单

分类 ZIP 根目录必须包含 `kb.yaml`：

```yaml
schema_version: 1
category: constitution
name: 可选名称
source: 可选来源
license: 可选许可说明
```

`category` 必须是 `constitution`、`diet` 或 `formula`，并与导入表单一致。只接受单行 `schema_version`、`category`、`name`、`source`、`license`，拒绝未知/重复字段和超过 16 KiB 的清单。综合导入不强制清单，提供时类别须为 `composite`。

清单验证声明一致，不证明内容语义或医学有效性。原始库拆分 ZIP 在打包阶段添加即可，源文件不变。公开 `templates/kb/` 已加入默认体质清单，导入其他类别前需修改。

## 3. 严格分类模式

新增 `TCM_KB_STRICT_CATEGORIES`：

- 未设置或为空：兼容模式，未配置专用根的类别可回退旧 `TCM_KB_ROOT`；
- `1`：严格模式，只使用各类专用根，缺类立即隐藏对应信息。

设置页提供开关和环境锁定处理。切换只改变回退策略，不修改综合库文件。应在三类专用库验证后开启，不自动清空 `TCM_KB_ROOT`。

## 4. 资源与写入闸门

词典最多 512 个键、每键 64 个别名、单个键或词条 128 字，限制无界正则展开；原库规模远低于上限。

新增 `src.record.has_formula_name()` 复用现有方名正则，不改原 `has_formula_content()` 语义。报告写入前新增类别闸门：

- 缺方剂库却输出方名或剂量：拒绝；
- 缺食疗库却输出结构化饮食建议：拒绝；
- 缺体质库却输出结构化辨证结论：拒绝。

闸门只检查本次模型输出，不把旧记录存量内容误算为本次违规。自由 Markdown 的全案仍采用保守隐藏，未实现可靠的逐段结构化拆分，也不宣称能解决全部模型不遵守提示的情况。
