# B05 指标注册表与重复概念归一迁移说明（2026-10-26）

> 范围：44 项指标元数据、舌色与黄染两个垂直切片、其余指标迁移、卧蚕归一、
> 字段级术语、17 项问诊及出处纠偏。
> 本批不重写预警引擎（B06），不改变动态/触诊/毫米测量的实际采集通道（B07），
> 不新增或重新签认医学权重（留待 B08），不批量改写历史记录。

## 1. 单一事实来源

新增 `src/indicators.py`：

- `IndicatorSpec`：全局 `id`、维度内 `key`、A/B/C `paths`、选项、prompt 映射、
  `allowed_methods`、`unknown_semantics`、字段级 `glossary`、出处、复核要求、
  参考项、别名与预警链接。
- `IndicatorRegistry`：提供 `for_field()`、`for_dimension()`、`for_prompt()`、
  `prompt_options()`、`observe_map()`、`glossary_for()` 和 `normalize_observation()`。
- `DIMENSION_INDICATORS`：供 `DailyRecord` 和校验器使用。`record.py` 的旧
  `_DIMENSION_INDICATORS` 仅作为兼容别名保留，新代码不应再复制路径表。

全局 ID 示例为 `tongue.body.color`、`eye.jaundice`；写入记录时仍使用原有
`body_color`、`jaundice` 等维度内字段名，A/B/C 的存储路径不变。

`options` 是修正选项来源，`prompt_options` 是识图封闭枚举来源。二者可以因
「未见异常」人工占位、显示去重或历史兼容词而不同，但都来自同一个 spec；
本批不声称所有字段的两组词完全相同。

Web 的 `FIELD_OPTIONS`、`REF_FIELDS`、`REVIEW_FIELDS`、`INDICATOR_LABELS`
继续作为兼容导出，实际定义已迁入注册表。显示层的同义词去重与 `NORMAL_OPTION`
保留在原 UI 语义中。

## 2. 黄染：一个规范概念，保留旧记录

规范字段为 `eye.jaundice`。`sclera_color` 中旧的 `黄染`、`黄染轻度`、
`黄染明显` 会在规范化观察视图迁入 `jaundice`，原始 JSON 不变。

- A 中文键、B `observations`、C 顶层英文键均支持旧别名。
- `DailyRecord.get_observation()` 和直接调用 `score* / assess*` 使用同一归一逻辑。
- `sclera_color` 不再对阳性黄染另行计分；`无黄染` 的旧正常表述仍兼容。
- 新旧字段都有值时，以中文分号保留双方证据；不把一个阳性值当作另一个的重复文本，
  也不让「无黄染」遮住旧字段的阳性值。

既有程度词及分值不变：泛称/轻度 4，明显 8。删除的是旧 `sclera_color=黄染`
重复评分入口。其他独立异常仍按原非舌维度累加、封顶 10 的规则计算，因此
黄染 8 加原有红血丝 3 得 10 是保留原规则，不是黄染重复。

这是重复概念 bug 修复。旧 `score()` / `score_indicators()` 的未命中返回 0
契约保留，但不承诺继续复现重复计分结果。

## 3. 卧蚕：归入眼部水肿

`eye.edema` 是卧蚕的唯一规范字段。旧 `face_edema=卧蚕` 在读取时迁移到该字段，
新 prompt 的头面部浮肿选项不再包含卧蚕。

旧记录同时写有头面与眼部卧蚕时，只在眼部计算既有 6 分，不再两处累计。
其他面肿、眼睑浮肿字段及分值不变。派生输入哈希基于归一后的观察，因此等价的
旧别名记录与规范记录具有一致指纹。

## 4. Prompt、映射、术语与问诊

- `scripts/vision_client.py` 保留拍摄安全、点刺存疑、危重舌象等原有说明，
  封闭枚举由注册表展开；缺占位符时显式报错，不静默漏字段。
- 补齐舌苔润燥、舌面瘀斑瘀点、舌底瘀点的封闭枚举与写入映射；齿痕、裂纹、
  胖瘦、点刺等扁平输出别名可进入规范路径，未识别内容仍进入 `_raw`。
- 皮肤「烟熏」使用既有评分标识，沿用原 5 分；舌体稍胖/略瘦、唇色淡粉红、
  耳色淡红等只对齐既有规则或正常语义，不新增权重。
- 甲床「粗糙」仍无评分词，新接口返回 unknown，不补造分值。
- 术语按「字段＋词」解释：面色红赤、目赤红赤、耳色红赤分别说明；鼻翼扇动的
  「明显」与黄汗的「明显」不再串义；无字段特化解释时保留通用白话注解。
- 问诊为 16 项骨架＋第 0 项手足温凉＝17。模板中的 0–16 编号、问题文本和
  M/17 均与向导 `INQUIRY_SPEC / INQUIRY_ITEMS / INQUIRY_TOTAL` 对照测试。

## 5. 出处与验证边界

`SourceRef` 保存 `source_id`、文件 SHA256、检索关键词与定位信息；来源区分
`tcm-textbook`、`jingfang` 和 `experience`，经验值不冒充原著量化标准。

本批纠正下睑血少证据链（L7228/L3595）、唇甲（L7228）、伤精（L3603）、
伤营（L3595）、黄汗（L4184）等定位，并同步 `docs/VOCAB_PROVENANCE_2026-10-16.md`。
甲床「甲错」没有教材指甲版依据，旧字段暂保留并显示复核提示，不因兼容而伪托教材。
舌下「淡紫」正常基线明确为现代经验来源。

固定文件哈希均与原著审查一致：

- 《中医诊断学》PDF：`88496913d72b514865b8076cfb24e1d5524606b67b7a3facb594d908eefe9db7`。

## 6. 派生版本与调用方迁移

- `SCORING_RULESET_VERSION = 2026-10-26.b05.1`
- `DERIVED_GENERATOR_VERSION = 2026-10-26.b05.1`

报告沿用 B04 的输入哈希、规则版本和生成器版本比较逻辑；需要重算的旧结论
由用户显式重新生成，不自动请求模型，也不回填伪造的采集信息。

调用方继续通过 `DailyRecord.get_observation()` 取得规范观察；直接使用评分接口
也会归一旧别名。新代码使用 `assess*`，不要把旧 `score*` 的 0 当作已确认正常。
`allowed_methods` 是指标能力元数据，不代表本批已强制实现新的视频、触诊或测量通道。
