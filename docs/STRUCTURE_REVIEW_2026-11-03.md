# 系统架构与目录结构审查（v1.20.1）

**日期**：2026-11-03
**范围**：核心模型、Web、检索、知识库、记录事务、私有数据、测试与发布结构。只读评估后实施小范围结构优化，不改医学规则。

## 1. 合理的现有结构

- `src/` 保持标准库核心：观察、评分、预警、置信度、治理和检索职责明确，未发现核心库发起网络请求。
- `web/` 承载 Flask、配置、记录事务、模型出站和页面；`scripts/` 保持 CLI 与周报入口；`tests/` 使用合成 fixture 隔离真实配置和健康数据。
- `templates/` 同时保存提示模板、记录 schema 和非医学知识库模板；`governance/` 保存可校验的医学裁决清单。
- `knowledge_base/` 公开仅保留配置说明；`private_kb/` 是运行时导入副本；`private/` 是独立私有仓工作副本，三者职责不同，不应混用或相互重置。
- 记录写入具备文件版本检查、原子替换、备份与恢复机制；模型出站有同源重定向、响应限量和总时限；Markdown 先做 HTML 转义。

## 2. 已确认并修复的问题

### 双模块实例

`web/` 同时允许 `web.llm_client` 与 `llm_client`、`web.safe_fetch` 与 `safe_fetch` 两种导入，实测为不同模块实例。这会使测试 mock、缓存和配置状态分叉。

已将生产代码和测试统一为顶层导入，包括 `server`、`safe_fetch`、`date_utils`、`photo_store`、`time_utils` 和 `envfile`，并在 `tests/test_release_hardening.py` 增加 AST 静态守卫，禁止以后混用两种形式。

### 根目录 Web 文件归属不清

`lifecycle_store.py` 只被 Web 记录、恢复和删除流程使用，已移动为 `web/lifecycle_store.py`，内容未改。顶层导入路径不需要变化，根目录职责更清楚。

### 文档多但入口不足

历史审查和迁移文件数量较多，但大量文档互相链接，直接按日期移动会破坏引用。新增 `docs/README.md` 作为分类索引，不移动历史文件，也不改写旧结论。

## 3. 保留而不贸然重构的部分

- `web/app.py` 仍是较大的路由装配点，但拆分会涉及大量闭包配置和事务依赖。当前没有证据支持大拆分为优于小步修整，后续如继续扩大可按设置、记录、知识库路由分批抽取。
- `web/trends_store.py` 同时负责趋势与报告，但已有稳定测试覆盖。只按名称拆文件不会自动改善接口，不列入本轮。
- 不移动私有源知识库、私有仓工作副本、原始书籍或真实配置；`.gitignore` 继续阻止私有内容进入公开提交。
- 当前开发分支仍基于旧历史，不能直接推送。该问题属于发布迁移，不能靠调整目录解决。

- 未读取或修改原始知识库、真实配置或健康数据，未调用真实模型；未做真实医学、多设备或多进程并发验证。

## 结论

当前架构不需要大重构。最有效的结构优化是消除双模块实例、明确单文件归属并增加文档入口，而不是按名称全面移动目录。后续结构工作应以保持接口、可逆小步和完整回归为准。
