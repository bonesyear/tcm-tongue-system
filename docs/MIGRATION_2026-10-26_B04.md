# B04 Unknown 状态与派生失效迁移说明（2026-10-26）

> 范围：状态化评分、平人出口、派生元数据、报告过期、趋势规则版本。
> 本批不调整医学分值，不进入 B05 指标注册表重构，不改变形状 A/B/C 的读取兼容。

## 1. 新评分接口与旧接口的关系

新增：

- `src.scoring.assess_indicators(dimension, observation) -> dict[str, ScoreResult]`
- `src.scoring.assess(dimension, observation) -> ScoreResult`
- `src.scoring.SCORING_RULESET_VERSION`

`ScoreResult` 包含 `state`、`value`、`matched_terms`、`unknown_indicators`、`missing_indicators` 和 `ruleset_version`。

| state | 含义 | value |
|---|---|---|
| `normal` | 命中明确正常词、正常基线或明确否定 | 0 |
| `abnormal` | 命中异常规则 | 原规则分数 |
| `unknown` | 有文本但无法判读或不在当前词表内 | `None` |
| `not_applicable` | 指标缺失、无评分规则或不适用 | `None` |

`missing_indicators` 与 `unknown_indicators` 分开：缺失不等于无法判读，未知不等于未观察。

旧 `score()` / `score_indicators()` 为兼容仍保留原数值行为（未命中返回 0）。**新调用方不得再用旧数值结果判断“正常/未知”。** 旧形状和既有测试不因新接口被迫改写。

## 2. 聚合与展示

- 有异常指标时按原规则聚合，并同时保留未知项；无异常但有未知时，维度不得称为正常。
- 总分只累计已知分数，未知项单独计数；严重度仍沿用原六维分母，不因覆盖不足而放大。
- 页面字段、维度、速览和趋势均显示“未知”，不再用空白或 0 徽章代替。
- 正常自由文本采用保守识别；例如“隐约浅淡蓝紫色，大致正常”“不粗”不会被误判为未知。“不典型”不会被当作正常。
- 原 `compute_dimension_deviation_detail` 的 `score/max/n` 结构不变；`unknown/missing` 统计由独立 `compute_dimension_state` 提供。

## 3. 平人出口

代码与 prompt 统一使用以下条件，必须同时满足：

1. 至少一维真实覆盖；
2. 已覆盖且可评分的指标全部正常；
3. 无未知项；
4. 无阳性问诊；
5. 无危险信号。

输出只能写“本次已采集项目未见已知异常”，同时列出未覆盖与未知项，**不得写“健康状态良好”或把筛查结果称为“平人”**。声明正常仍不算真实覆盖。代码侧第二道防线也使用同一判断，不再只检查全 0。

## 4. 派生元数据

`src/derived.py` 提供 `observation_input_hash()` 与 `current_derived_meta()`：

- `input_hash`：规范化六维观察、问诊和上下文的 SHA256，形状 A/B/C 规范化后一致；
- `scoring_ruleset_version`：评分规则版本；
- `generator_version`：派生生成器版本；
- `updated_at`：本次修正/组装/生成时间。

新报告额外保存 `input_hash`、`ruleset_version`、`generator_version` 和已有的 `prompt_template_version`。修正与向导组装同步更新 `derived_meta`。

## 5. 报告过期规则

`web/trends_store.report_state()` 比较当前观察与报告元数据：

- 哈希不一致：观察或问诊已变化；
- 评分规则、生成器或 prompt 模板版本不一致：派生基础已变化；
- 历史报告没有哈希时，取 `corrected_at` 与 `derived_meta.updated_at` 的较晚者，只有其晚于 `generated_at` 才判过期，**不会仅因缺新字段就全部过期**。

修正或 merge 后，旧报告和旧结构化结论不再作为当前结论展示，并显示过期原因和重新生成入口；未配置辨证模型时改为当前本地速览。元数据匹配的历史报告仍正常展示。

## 6. 趋势与规则版本

周报新增：

- `unknown_counts.first/last/total`；
- `rule_versions`（`legacy` 或记录的 `derived_meta.scoring_ruleset_version`）；
- `mixed_rule_versions`；
- `scoring_ruleset_version`（当前计算引擎版本）。

同周存在多个来源版本时明确标记，图表按当前规则重算，不把规则差异静默解释为病情变化。未知值在图表中为 `None`，任何一端未知都不作趋势判定；一端无有效观测的原文案保持兼容。

## 7. 调用方迁移建议

- 新代码使用 `assess` / `assess_indicators`，处理 `None` 前不得直接算术比较。
- 不要把 `unknown_count == 0` 当作健康证明，它只表示没有无法判读的指标。
- 不要把 `not_applicable` 与 `unknown` 混为一谈。
- 报告展示前调用 `report_state()`，不要只检查报告文件是否存在。
- 历史记录没有 `derived_meta` 时按 `legacy` 处理，不回填伪造的采集质量或时间。
