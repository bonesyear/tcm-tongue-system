# B01–B03 行为与接口迁移说明（2026-10-26）

> 范围：Web 数据安全、核心记录与覆盖语义、检索/校验/周报可靠性。
> 本批不调整医学分值，不引入 B04 的 Unknown/派生失效重构。

## 1. 核心记录与配置

### 形状回退与空记录

- `vision_analysis` / `diagnosis` 新键为 `null` 时，会继续回退到旧名或其他别名，不再吞掉旧数据。
- `observations` 为空壳且存在 `vision_analysis` 时，改按形状 A 解析并输出 stderr 告警。
- 只有空 `observations`、没有形状 A 数据的记录仍是合法零覆盖 B 记录，**不新增告警**；这不是无法判定的形状。
- 声明正常占位只影响所在指标；同维度存在真实观察时仍计覆盖，纯占位维度仍不计覆盖。Web 展示使用同一语义。
- `is_covered` 的字典与纯文本入口都会先去除字符串首尾空白再判断。

### `from_coverage`

`from_coverage` 现在只接受 `int` 或 `None`：

- `None` 按无覆盖信息处理，返回 LOW；
- 原 0–6 及超界映射不变；
- `str`、浮点、布尔和容器不再被静默转换或截断，而是抛出带纠正说明的 `TypeError`。

调用方应在边界显式转换为整数，不要依赖旧的 `"3"` 或 `3.7` 隐式行为。

### `TCM_DATA_ROOT`

- 未设置或纯空白：使用 `REPO_ROOT`；
- 绝对路径：规范化后使用；
- 相对路径：解释为相对 `REPO_ROOT`，不再随进程当前工作目录变化。

配置仍在模块 import 时确定。若部署脚本依赖旧的“相对当前 cwd”行为，应改为绝对路径或相对仓库根的新路径。

## 2. 检索与周报

### `retrieve()` 输入与大小写

- 字符串查询先 `strip`；空串返回空结果；非字符串/非字符串列表抛 `TypeError`。
- 串首、串尾或连续 `AND` 抛 `ValueError`，不再静默当普通词检索。
- `retrieve` / `retrieve_and` 的 grep 路径与 RAG 统一为 ASCII 大小写不敏感。
- 底层 `search()` / `search_and()` 的原始正则语义不变，默认仍大小写敏感。

### RAG 合并与失败回退

- RAG chunk 带 `end_line`；与 grep 合并时按行范围判重。chunk 内若还有 grep 未覆盖行，就保留为补充证据，不再仅按首行去重。
- Embedding 模型加载或编码失败时输出 stderr 告警并回退 TF-IDF；未实际下载模型。

### 周报与校验

- 合法 JSON 但非对象的记录会跳过并告警；数值 date 转字符串后再用于趋势标签。
- 非法 date 会明确告警；`YYYY-W00` 占位周名附加安全化的 end_date，避免不同坏日期周报互相覆盖。
- 中文“副本/备份/快照”文件不参与档案选择。
- 形状 B `danger_flags` 的附加元数据可存在，结构校验本身不放松。
- validator 在 GBK 控制台以替换不可编码字符的方式继续输出，退出码语义不变；UTF-8 输出不变。
- 性能评估后未增加缓存：`generate_weekly_report_data` 已复用每条记录的 `DailyRecord`，别名词典、grep 和 RAG 也已有缓存，没有证据支持额外缓存层。

## 3. Web 输入与写入

- `dim` / `indicator` / `value` 必须为字符串；JSON null 不再落库成 `"None"`。
- 向导 `mode` 只接受 `new` / `merge`，危险确认只接受 `keep` / `fix`。
- 设置保存和拍照使用点共享视觉数值校验；非法温度/超时返回 400 且不写入 `.env`。历史坏配置在拍照时同样返回 400。
- 设置页的模型、温度和超时会完整传入真实识图调用；清空可选配置时移除旧环境值。
- 非空库 `/demo` 返回 409；同名文件使用独占创建，不能覆盖真实记录。
- 修正、向导提交、报告、恢复、草稿和 `.env` 使用独立临时文件与原子替换；并发校验也各自使用独立临时文件。
- 趋势按文件名日期处理内部/文件名日期不一致并告警；雷达图例显示真实首末记录日。
- 知识库引用先给当日体征预留一半配额，通用食疗/煎服锚词补余量。
- 形状 A 的“六病定位/核心病机”使用中文键回退展示。

## 4. 仍未解决的边界

原子替换只保证不写坏单个文件，**不保证并发读－改－写不丢更新**。同一记录不同字段并发修正、同一草稿多端编辑仍可能后写覆盖先写；该风险记录在 `docs/KNOWN_ISSUES.md` #21，后续用版本冲突检测处理，不在本批宣称解决。

调用方若依赖旧行为，应按上述说明调整；完整回归与真实路径验收见 `CHANGELOG.md` v1.8.35。
