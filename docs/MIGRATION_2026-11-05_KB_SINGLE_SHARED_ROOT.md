# 单一综合回退根修正与系统验收（v1.20.21）

**日期**：2026-11-05

**范围**：复核知识库拆分、共享综合根及独立启停后的检索与报告行为，修正单一综合回退根的类别越界；验收真实 HTTP、隔离浏览器异常路径和 Windows 干净部署。除统一视图构建及其缓存版本外，不改变检索算法、医学规则、评分、权重或剂量策略。

## 1. 问题与行为变化

### 现象与根因

当开关或配置使三个类别中只剩一个类别使用综合根时，该根在 `active` 中只出现一次。旧 `_build_view()` 仅把被两个以上类别引用的根识别为共享综合根，因此将这个完整综合根误当成该类专用根。食疗和方剂等可明确归属其他类别的标准目录也会被复制，并标为当前唯一类别的候选。

例如只剩体质类别回退到综合根时，`diet-lifestyle/` 与 `formulas/` 的正文可能进入体质候选及模型输入，不再等价于完整综合根排除这两类后的检索子集。

### 修复

`web/kb_view.py` 现在对单一有效类别也检查标准顶层目录：

- 当前类别对应的标准目录继续保留；可明确归属其他类别的 `diagnostics/`、`diet-lifestyle/`、`formulas/` 被剔除，不进入候选或报告输入。
- 自定义专用目录及无法判类的普通目录保留原有专用根兼容行为；本次不按未知综合布局额外拒绝或猜测归属。
- 多类别共享根、独立专用根、重复路径处理及全局候选预算逻辑不变。

`_VIEW_SCHEMA` 从 2 升为 3。旧派生视图因版本不匹配自动重建，重建同路径前仍按既有流程失效文件行与 RAG 缓存。无需手工删除缓存，不修改源知识库或其 ZIP；如需人工清理缓存，仍须先停止服务。

## 2. 回归证据

新增 `test_unified_single_shared_root_excludes_inactive_categories`，分别对体质、食疗和方剂构造“完整综合根只启用一个类别”的场景。预期值为完整综合根删除其他两个标准目录后的直接检索，并统一加上当前类别标记。修复前三个场景均失败，修复后候选内容、顺序和类别归属一致。

既有损坏清单测试改为读取 `kb_view._VIEW_SCHEMA`，不再写死旧版本号；没有为了兼容旧缓存而回退产品 schema。

- 知识库视图与统一检索聚焦：**34 passed**。
- 本阶段全量：**1103 passed、1 skipped**。
- `docs/KNOWN_ISSUES.md` 新增并关闭 #45。

## 3. 知识库只读差分

知识库 ZIP 均在工作区隔离副本中验收，不读取真实配置或健康记录。查询集由默认锚词、别名词典键以及额外 AND／OR／无命中查询组成，共 **84 个查询、72 个别名键**。

- 三种单类、三种双类和完整三类共 **7 种非空组合**。
- 拆分布局与完整综合布局：**588 组**比较。
- 共享综合根与对应完整布局子集：**588 组**比较。
- 各启停迁移与恢复基线：**672 组**比较。
- 比较覆盖 Grep／RAG 方法、命中数、文件、行号、正文、上下文、排序、别名展开、候选及 `build_report_input()` 模型输入；结果全部一致。
- ZIP 隔离副本及解压副本前后哈希不变，类别状态亦逐项核对通过。

这里的“一致”仅指相同确定性代码路径下的检索、候选和模型输入一致。未调用真实模型，不宣称真实模型逐字输出相同，也不宣称医学准确性已经标定。

## 4. 新旧报告真实 HTTP 验收

通过隔离服务实际访问详情、设置和重新生成路由，共 **50 次请求、164 项断言**，真实模型调用为 **0**：

- 2 个候选场景：核对新报告与缺少新版类别元数据的旧报告，在类别停用和恢复后的正文隐藏、候选过滤及恢复显示。
- 4 个严格模式重生成场景：覆盖新旧指纹在普通模式与严格模式之间双向切换后的过期、旧正文隐藏、模拟模型重生成及恢复当前状态。
- 严格模式按综合根是否实际参与检索比较旧版综合指纹；有效来源恢复且指纹一致时不误报过期。
