# 三类知识库独立导入与显示闸门迁移（v1.17.0）

**日期**：2026-11-03
**范围**：把原单一知识库运行链扩展为中医体质辨证、食疗、方剂三类，分别导入、检索、保存状态，并按类别控制前端显示。原始线下知识库不做物理拆分、移动或删除。

## 1. 配置与兼容

| 类别 | 标识 | 专用变量 | 程序管理副本 |
| --- | --- | --- | --- |
| 中医体质辨证 | `constitution` | `TCM_KB_CONSTITUTION_ROOT` | `<TCM_DATA_ROOT>/private_kb/constitution/` |
| 食疗 | `diet` | `TCM_KB_DIET_ROOT` | `<TCM_DATA_ROOT>/private_kb/diet/` |
| 方剂 | `formula` | `TCM_KB_FORMULA_ROOT` | `<TCM_DATA_ROOT>/private_kb/formula/` |

`inspect_kb_categories()` 按“专用根优先、旧综合库回退”解析：某类未设置专用变量时，可读取 `TCM_KB_ROOT`，但不会回退到另一类专用库。专用根即使不存在或为空，也不回退综合库，避免把错误配置掩盖成可用。

旧 `composite` 导入接口继续写 `TCM_KB_ROOT` 并覆盖 `private_kb/`。新分类导入只覆盖本类副本并写本类变量；嵌套父目录会在激活前创建。原有 ZIP 限制、管理员闸门、失败回滚和缓存清理保持不变。

## 2. 分类检索与报告元数据

报告按类别检索：体质库使用当日体征词，食疗库补充忌口/适宜/食疗，方剂库补充煎服/温覆/方证/方剂。各类分别记录 `unconfigured / empty / error / no_hits / retrieved`，一类失败不会伪装成另一类成功。

新报告增加 `kb_categories`，每项保存状态、根、版本、错误和该类候选参考；`kb_status`、`kb_root`、`kb_revision`、`kb_refs` 继续保留供旧消费者使用。旧报告没有分类元数据时仍按兼容路径展示，但必须通过当前类别显示闸门。

读取详情时，任一类根或版本变化都会使报告过期。报告准备期间任一类变化会返回错误，避免混合不同版本。

## 3. 缺类显示规则

| 缺失类别 | 前端行为 |
| --- | --- |
| 中医体质辨证 | 隐藏体质格局、四证、辨证提要、全案和该类候选参考 |
| 食疗 | 隐藏饮食宜忌、食疗建议及该类候选参考 |
| 方剂 | 隐藏方药内容、完整方药报告及该类候选参考 |

本地速览仍按内置规则计算，但只有对应类别 `ready` 才显示；内置映射不再成为缺库时的显示回退。旧记录或模型原始输出中即使已有内容，也不能绕过当前类别状态。

自由 Markdown 无法可靠按医学类别切割，因此缺体质或方剂时保守隐藏相关全案，不宣称完成精细文本过滤。食疗结构化为独立建议字段，可以单独隐藏。缺类时模型输入也明确禁止生成对应内容，但代码显示闸门仍是最终边界。
