# 自建知识库格式与导入规范

本规范面向从公开仓 clone 后自托管的使用者。你可以把**自己有权使用的文献、笔记和别名词典**整理为本地 ZIP，再从设置页导入。公开仓不提供原知识库文件或在线下载；本规范与模板也不包含原库原文。

如果要跟着 AI 从一本中医著作开始，逐步完成读取确认、分批生成、原文复核、打包、导入和验证，先读[从中医著作到知识库](kb-guide.md)；本文保留完整技术约束。

**个人自建知识库时，只需用 AI 制作一个综合知识库 ZIP，不必再拆成体质、食疗、方剂三个子库或三个 ZIP。** 三类专用包用于确有按类独立提供、更新和重置资料需求的场景，不是个人建库的额外步骤。综合包内的标准目录只用于主题归类，不是三个子库。

## 1. 先确认边界

- 你须自行确认文献的复制、整理和使用许可，并核对内容准确性。能阅读不等于有权复制或再分发；不要把私有 ZIP、原文或衍生笔记提交到公开仓。
- 导入只改变本地检索语料与别名词典，**不训练或微调模型**，也不会自动修改医学权重、指标词表、红线分类、评分、置信度、方剂或剂量策略。
- 结构校验通过只说明文件可读、格式受支持，不表示医学内容真实、完整或获得专业认可。模型仍可能错误理解或引用资料，输出须人工复核，不能作为诊断依据。
- 未配置知识库时，记录、评分、趋势和本地规则速览仍可使用；检索会按既有行为返回空结果或告警，不伪造引用。照片判读仍由你配置的视觉模型或手动录入完成。

## 2. 目录与文件格式

综合知识库 ZIP 在仓库外另建工作目录，按实际内容使用三个标准目录；著作没有的类别直接省略，不要补写：

```text
my-kb/
├── kb.yaml                  # 可选但推荐：category 为 composite
├── diagnostics/             # 体质、体征、辨证资料
│   └── topic.md
├── diet-lifestyle/          # 食疗、饮食宜忌资料
│   └── topic.md
├── formulas/                # 方剂、方证、煎服资料
│   └── topic.md
└── synonym_map.yaml         # 可选：根目录别名词典
```

至少保留一份非空 Markdown。确有跨类、无法确定归属的笔记时，可放在 `notes/` 等普通目录作为通用候选，但能归类的资料优先使用上述三个标准目录。[`templates/kb/`](../templates/kb/) 是**分类专用包**的非医学合成模板，不是综合包必填结构。通用格式规则如下：

| 项目 | 要求 |
| --- | --- |
| 文本 | UTF-8，允许起始 BOM |
| 文件类型 | 仅 `.md`、`.yaml`、`.yml`；扩展名不区分大小写 |
| 必要内容 | 至少一份非空 Markdown |
| ZIP 大小 | 不超过 8 MiB |
| 文件数 | 最多 32 个，不含目录条目；ZIP 总条目最多 64 个 |
| 单文件 | 展开后不超过 4 MiB |
| 总展开大小 | 不超过 32 MiB |
| 压缩比 | 单文件不超过 200；仅 Stored 或 Deflated |
| 路径 | 使用相对 POSIX 路径；不接受绝对路径、`..`、反斜杠、盘符、隐藏路径、重复或大小写冲突路径 |
| 特殊条目 | 不接受加密 ZIP、符号链接或特殊文件 |

`README.md` 是说明文件，任何层级中这个**精确大写文件名**都不会作为检索证据；`readme.md`、`Readme.md` 等其他大小写会作为正文检索。说明文字请统一使用大写 `README.md`，有效内容请放在其他 Markdown 文件中。ZIP 可以包含一层普通文件夹，但根目录的 `synonym_map.yaml` 才会被当作默认词典，建议按上面的结构直接打包文件。

### Markdown 与来源信息

检索按真实文本行工作，不要求固定医学章节或专用 front matter。建议每份资料用清晰标题和小节组织，并在文首保留以下来源元数据，方便人工追溯：

```markdown
# <自定义主题>

来源：<书名、作者、版本、页码或 URL>
许可：<你确认的使用许可或授权依据>
整理日期：<YYYY-MM-DD>
整理说明：<原文、节选或自行总结；如有改动请说明>
```

这些字段是**推荐约定，不是医学有效性认证**，当前导入器不会根据字段判断许可或临床质量。不要伪托出处，不要把模型生成内容标成原文。

### `synonym_map.yaml`

为兼容没有安装 PyYAML 的环境，使用顶层字符串键和缩进字符串列表的受限 YAML 子集：

```yaml
# 注释与空行可以保留
自定义口语:
  - 自定义规范词
  - 另一个规范词
```

- 键和值使用单行非空字符串；推荐使用上面的 block 列表，不使用 flow 列表、锚点、多行块或复杂对象。
- 每个键表达一组查询扩展；原查询词会自动保留，无需在列表中重复。
- 避免重复键和过宽别名。别名只扩展检索，不会变成评分词或医学判断规则。
- 词典可省略；省略后仍按原词检索。
- 资源上限：最多 512 个键、每键 64 个别名、单个键或词条 128 字。

### 知识库清单 `kb.yaml`

综合 ZIP 可以省略 `kb.yaml`；为了记录资料名称、来源和许可，推荐在根目录提供：

```yaml
schema_version: 1
category: composite
name: 自定义资料名称
source: 来源说明
license: 使用许可或授权依据
```

综合包如提供清单，`schema_version` 必须为 `1`，`category` 必须为 `composite`。`name`、`source`、`license` 为可选单行元数据；不接受嵌套、未知或重复字段，清单最大 16 KiB。

分类专用 ZIP 的根目录**必须**包含同一格式的清单，其 `category` 为 `constitution`、`diet` 或 `formula`，并与导入表单一致。清单只验证用户声明与导入类别一致，不证明内容确实属于该领域，也不构成医学或许可审核。

## 3. 分类与综合打包导入

### 三类专用包

设置页前方的「子知识库」分组默认折叠，展开后可独立更新、重置和配置三类专用包：

| 类别 | 表单类别 | 配置变量 | 导入副本 | 缺少时不可显示的信息 |
| --- | --- | --- | --- | --- |
| 中医体质辨证 | `constitution` | `TCM_KB_CONSTITUTION_ROOT` | `private_kb/constitution/` | 体质格局、四证和辨证内容 |
| 食疗 | `diet` | `TCM_KB_DIET_ROOT` | `private_kb/diet/` | 饮食宜忌与食疗建议 |
| 方剂 | `formula` | `TCM_KB_FORMULA_ROOT` | `private_kb/formula/` | 方药、方义及完整方药报告 |

上述路径均以 `<TCM_DATA_ROOT>` 为父目录。分类导入处理对应专用副本并写入对应变量，未配置的专用根默认回退综合库。整组开关 `TCM_KB_CATEGORIES_DISABLED=1` 会暂停三个子库及综合回退，但不覆盖各子库自身选择；恢复整组后按各子库原选择生效。`TCM_KB_STRICT_CATEGORIES=1` 开启严格分类模式后只认专用根，综合库不参与检索；该模式独立于整组开关，开启前应分别验证三类专用库。

### 综合包

综合导入位于子知识库分组之后，用于一个 ZIP 包含多类资料。完整的著作整理、原文复核和导入步骤见[从中医著作到知识库](kb-guide.md)，格式约束如下：

1. 按实际内容使用 `diagnostics/`、`diet-lifestyle/`、`formulas/`，加入可选的根目录 `kb.yaml` 和 `synonym_map.yaml`；著作未涉及的类别直接省略。
2. 将综合目录的**内容**打成 ZIP，不要再嵌套一层 `my-kb/`。原稿、OCR、核对记录和失败草稿留在 ZIP 外。
3. 在「设置 → 知识库」的综合知识库卡片选择 ZIP 并提交；非回环访问须先验证管理口令。导入本身不调用模型。
4. 系统完整校验文本、根目录词典和可选清单后，替换综合导入副本并写入 `TCM_KB_ROOT`，保留三类分类专用副本。

综合包不得包含 `constitution/`、`diet/`、`formula/` 这三个系统保留目录；它们与用于识别综合包内容的三个标准目录不是同一组名称。新 clone 默认不读取外部旧目录，程序管理副本会在导入后自动启用。`TCM_KB_COMPOSITE_DISABLED=1` 只暂停综合根及分类回退，不影响已配置的独立专用根。

所有开关只控制对应内容能否参与检索、模型报告和本地速览，不删除知识库文件。

## 4. 覆盖与原库保护

- **综合导入是替换而非合并**：每次成功导入替换 `<TCM_DATA_ROOT>/private_kb/` 综合副本，保留其中的分类专用子目录。新 ZIP 必须包含希望继续使用的全部综合资料。
- **分类导入只替换本类副本**：目标为 `<TCM_DATA_ROOT>/private_kb/<类别>/`，不合并 ZIP，也不改变其他类别。两种导入都不会移动、覆盖或删除当前配置指向的外部原库。请勿把唯一原稿放进导入副本目录，并自行备份原稿与需要保留的旧 ZIP。
- **导入只解除本类自身停用**：分类导入清除对应的 `TCM_KB_<类别>_DISABLED`，综合导入清除 `TCM_KB_COMPOSITE_DISABLED`；均不自动开启整组或改变其他类别选择。因此，整组仍关闭时，导入成功不等于内容已经参与检索。
- 设置页「重置本类知识库」只删除本类导入副本，并设置 `TCM_KB_<类别>_DISABLED=1`。停用优先于综合库回退，对应信息不可显示；上传新 ZIP 只恢复本类自身启用状态，整组选择保持不变。重置不会删除或修改外部原库和其他类别。
- 非法 ZIP、文本错误、词典错误或激活失败时，保留本次导入前的副本及原配置。配置写回失败时，新副本保留在同级 `.kb-failed-<随机串>/` 供诊断，并同时恢复写入前的配置和旧副本；其他类别和外部原库不受影响。若配置回滚也失败，会明确报错而不是宣称已恢复。
- 成功后系统清理对应根的词典、文本和 RAG 缓存，无需重建模型。导入期间尽量避免同时检索；同一 Web 进程内的导入与配置写入会串行执行。
- 统一检索可能在 `<TCM_DATA_ROOT>/cache/kb-unified/` 自动创建派生视图。它只是可删除重建的缓存，不是知识库来源，不需要导入或备份；删除后系统会按当前源库重建，不会修改源目录或导入 ZIP。**运行中的缓存由系统管理，人工清理前请先停止服务**，不要删除正在读取的视图。
- 如果对应变量来自系统环境变量，页面不会改写 `.env`，响应中的 `configured=false` 表示变量未改。导入副本仍会生成，但当前类别继续由环境变量决定；如要使用副本，请自行修改部署配置。

## 5. 导入后核对

1. 在设置页确认综合库及所用类别的状态和可检索 Markdown 文件数，并检查整组、各子库和综合开关；完整路径位于「技术详情」。采用分类时，还要检查缺类对应的信息确实不可显示。
2. 用一个确定存在于资料中的词测试检索，再测试词典中的口语键，确认来源文件和别名扩展符合预期。
3. 抽查模型报告中的候选参考，回到本地原文人工核对。结构可检索不等于资料相关，更不等于模型实际引用或医学结论成立。

报告生成会显式使用各类别当前有效根，保存 `kb_categories` 及兼容字段；任一类根、版本或启停导致有效来源变化时，旧报告提示过期，恢复原状态且指纹一致后可继续显示。未配置、空库、无命中和检索失败按类别分别披露。缺方剂的方名/剂量、缺食疗的结构化饮食、缺体质的结构化辨证输出会在写入前拒绝。候选条文在送入模型前按每类单条 1200 字、总计 12000 字截断，并标记为不可信资料而非指令；请自行控制文献质量，不要把提示指令当作医学内容导入。

共享综合库使用 `diagnostics/`、`diet-lifestyle/`、`formulas/` 三个标准目录识别专类。三类全部可用时，根目录或 `notes/` 等其他位置的 Markdown 会作为 `composite` 通用候选单独送入模型，不会被冒称为体质资料；缺少任一类别时，这种无法确定归属的共享资料会明确报错并关闭本次候选，避免夹带缺类内容。需要缺类运行自定义布局时，请按类别制作专用 ZIP；专用根中的普通子目录仍按导入类别处理。`composite` 只是溯源标记，不是第四类知识库。

公开合成模板只用于验证格式和检索链路，不含临床知识，也不能替代你自己的合法资料。

## 6. 综合包操作指南

从一本中医著作开始，使用 AI 核对读取范围、编制主题清单、分批生成正文、对照原书复核、制作综合 ZIP、导入并验收的完整步骤，统一见[从中医著作到知识库](kb-guide.md)。指南包含可直接复制的分阶段任务说明，本文不再另维护一套操作提示。

分类专用包的文件结构可使用 [`templates/kb/`](../templates/kb/) 中的非医学合成模板检查；该模板不包含临床知识，也不替代实际资料。
