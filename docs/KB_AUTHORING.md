# 自建知识库格式与导入规范

本规范面向从公开仓 clone 后自托管的使用者。你可以把**自己有权使用的文献、笔记和别名词典**整理为本地 ZIP，再从设置页导入。公开仓不提供原知识库文件或在线下载；本规范与模板也不包含原库原文。

## 1. 先确认边界

- 你须自行确认文献的复制、整理和使用许可，并核对内容准确性。能阅读不等于有权复制或再分发；不要把私有 ZIP、原文或衍生笔记提交到公开仓。
- 导入只改变本地检索语料与别名词典，**不训练或微调模型**，也不会自动修改医学权重、指标词表、红线分类、评分、置信度、方剂或剂量策略。
- 结构校验通过只说明文件可读、格式受支持，不表示医学内容真实、完整或获得专业认可。模型仍可能错误理解或引用资料，输出须人工复核，不能作为诊断依据。
- 未配置知识库时，记录、评分、趋势和本地规则速览仍可使用；检索会按既有行为返回空结果或告警，不伪造引用。照片判读仍由你配置的视觉模型或手动录入完成。

## 2. 目录与文件格式

可以直接从 [`templates/kb/`](../templates/kb/) 复制合成模板，在仓库外另建工作目录修改。一个最小知识库如下：

```text
my-kb/
├── README.md            # 可选：给读者看的说明，不参与检索
├── topic.md             # 至少一份非空 Markdown
└── synonym_map.yaml     # 可选：根目录别名词典
```

也可以按主题建立普通子目录，例如 `notes/topic.md`。规则如下：

| 项目 | 要求 |
| --- | --- |
| 文本 | UTF-8，允许起始 BOM |
| 文件类型 | 仅 `.md`、`.yaml`、`.yml`；扩展名不区分大小写 |
| 必要内容 | 至少一份非空 Markdown |
| ZIP 大小 | 不超过 8 MiB |
| 文件数 | 最多 32 个，不含目录条目；ZIP 总条目最多 64 个 |
| 单文件 | 展开后不超过 4 MiB |
| 总展开大小 | 不超过 32 MiB |
| 压缩比 | 单文件不超过 200；仅 Stored 或 Deflated |
| 路径 | 使用相对 POSIX 路径；不接受绝对路径、`..`、反斜杠、盘符、隐藏路径、重复或大小写冲突路径 |
| 特殊条目 | 不接受加密 ZIP、符号链接或特殊文件 |

`README.md` 是说明文件，任何层级的该文件名都不会作为检索证据；有效内容请放在其他 Markdown 文件中。ZIP 可以包含一层普通文件夹，但根目录的 `synonym_map.yaml` 才会被当作默认词典，建议按上面的结构直接打包文件。

### Markdown 与来源信息

检索按真实文本行工作，不要求固定医学章节或专用 front matter。建议每份资料用清晰标题和小节组织，并在文首保留以下来源元数据，方便人工追溯：

```markdown
# <自定义主题>

来源：<书名、作者、版本、页码或 URL>
许可：<你确认的使用许可或授权依据>
整理日期：<YYYY-MM-DD>
整理说明：<原文、节选或自行总结；如有改动请说明>
```

这些字段是**推荐约定，不是医学有效性认证**，当前导入器不会根据字段判断许可或临床质量。不要伪托出处，不要把模型生成内容标成原文。

### `synonym_map.yaml`

为兼容没有安装 PyYAML 的环境，使用顶层字符串键和缩进字符串列表的受限 YAML 子集：

```yaml
# 注释与空行可以保留
自定义口语:
  - 自定义规范词
  - 另一个规范词
```

- 键和值使用单行非空字符串；推荐使用上面的 block 列表，不使用 flow 列表、锚点、多行块或复杂对象。
- 每个键表达一组查询扩展；原查询词会自动保留，无需在列表中重复。
- 避免重复键和过宽别名。别名只扩展检索，不会变成评分词或医学判断规则。
- 词典可省略；省略后仍按原词检索。
- 资源上限：最多 512 个键、每键 64 个别名、单个键或词条 128 字。

### 分类清单 `kb.yaml`

每个分类 ZIP 的根目录必须包含 `kb.yaml`，声明格式版本和类别：

```yaml
schema_version: 1
category: constitution
name: 自定义资料名称
source: 来源说明
license: 使用许可或授权依据
```

`schema_version` 和 `category` 必填，`category` 必须为 `constitution`、`diet` 或 `formula`，并与导入表单一致。`name`、`source`、`license` 为可选单行元数据；不接受嵌套、未知或重复字段，清单最大 16 KiB。综合 `composite` 导入不强制清单，若提供则类别必须为 `composite`。

清单只验证用户声明与导入类别一致，不证明内容确实属于该领域，也不构成医学或许可审核。原始库拆分 ZIP 在打包时添加清单即可，无需修改源文件。

## 3. 分类、打包与导入

请按内容把资料分别打成 ZIP；每类有独立目录、配置和显示范围：

| 类别 | 表单类别 | 配置变量 | 导入副本 | 缺少时不可显示的信息 |
| --- | --- | --- | --- | --- |
| 中医体质辨证 | `constitution` | `TCM_KB_CONSTITUTION_ROOT` | `private_kb/constitution/` | 体质格局、四证和辨证内容 |
| 食疗 | `diet` | `TCM_KB_DIET_ROOT` | `private_kb/diet/` | 饮食宜忌与食疗建议 |
| 方剂 | `formula` | `TCM_KB_FORMULA_ROOT` | `private_kb/formula/` | 方药、方义及完整方药报告 |

上述路径均以 `<TCM_DATA_ROOT>` 为父目录。新 clone 默认不读取外部旧目录，程序管理副本会自动启用。`TCM_KB_STRICT_CATEGORIES=1` 开启严格分类模式，只认专用根，不再回退综合库；请在三类专用库验证后再开启。旧 `composite` 导入接口仍写 `TCM_KB_ROOT`，替换综合副本时保留分类子目录，但综合包不得包含 `constitution/`、`diet/`、`formula/` 这些保留目录。

1. 在自己的工作目录准备 Markdown 和可选词典，用系统压缩工具或 `zipfile` 分类打包。无需上传文献到项目方，也不需要调用模型。
2. 打开「设置 → 知识库」，在对应类别下选择 ZIP 并提交。非回环访问须先验证管理口令。
3. 系统先完整解包到暂存目录，校验文本和根目录词典；全部成功后才激活本类副本并写入对应变量。

新 clone 默认不读取外部旧目录。请通过设置页导入 ZIP，程序管理副本会自动启用；上传和重置只处理 `<TCM_DATA_ROOT>/private_kb/<类别>/`，不会删除外部源文件。

## 4. 覆盖与原库保护

- **每次成功导入都会先重置该类旧导入副本，再激活新内容并解除停用**，不合并 ZIP，也不改变其他类别。
- 替换目标始终是本类专用目录，**不是当前任何专用根或 `TCM_KB_ROOT` 指向的外部目录**。外部原库不会被移动、覆盖或删除。请勿把唯一原稿放进导入副本目录，并自行备份原稿与有需要的旧副本。
- 设置页「重置本类知识库」只删除本类导入副本，并设置 `TCM_KB_<类别>_DISABLED=1`。停用优先于综合库回退，对应信息不可显示；上传新 ZIP 后自动恢复。重置不会删除或修改外部原库和其他类别。
- 非法 ZIP、文本错误、词典错误或激活失败时，保留本类旧副本及原配置。配置写回失败时，新副本保留在同级 `.kb-failed-<随机串>/` 供诊断，并同时恢复写入前的配置和本类旧副本；其他类别和外部原库不受影响。若配置回滚也失败，会明确报错而不是宣称已恢复。
- 成功后系统清理本类根的词典、文本和 RAG 缓存，无需重建模型。导入期间尽量避免同时检索；同一 Web 进程内的导入与配置写入会串行执行。
- 统一检索可能在 `<TCM_DATA_ROOT>/cache/kb-unified/` 自动创建派生视图。它只是可删除重建的缓存，不是知识库来源，不需要导入或备份；删除后系统会按当前源库重建，不会修改源目录或导入 ZIP。
- 如果对应变量来自系统环境变量，页面不会改写 `.env`，响应中的 `configured=false` 表示变量未改。导入副本仍会生成，但当前类别继续由环境变量决定；如要使用副本，请自行修改部署配置。

## 5. 导入后核对

1. 在设置页确认每类路径、状态和可检索 Markdown 文件数；缺类时检查对应信息确实不可显示。
2. 用一个确定存在于资料中的词测试检索，再测试词典中的口语键，确认来源文件和别名扩展符合预期。
3. 抽查模型报告中的候选参考，回到本地原文人工核对。结构可检索不等于资料相关，更不等于模型实际引用或医学结论成立。

报告生成会显式使用各类别当前根，保存 `kb_categories` 及兼容字段；任一类根或版本变化都会使旧报告提示过期。未配置、空库、无命中和检索失败按类别分别披露。缺方剂的方名/剂量、缺食疗的结构化饮食、缺体质的结构化辨证输出会在写入前拒绝。候选条文在送入模型前按每类单条 1200 字、总计 12000 字截断，并标记为不可信资料而非指令；请自行控制文献质量，不要把提示指令当作医学内容导入。

共享综合库使用 `diagnostics/`、`diet-lifestyle/`、`formulas/` 三个标准目录识别专类。三类全部可用时，根目录或 `notes/` 等其他位置的 Markdown 会作为 `composite` 通用候选单独送入模型，不会被冒称为体质资料；缺少任一类别时，这种无法确定归属的共享资料会明确报错并关闭本次候选，避免夹带缺类内容。需要缺类运行自定义布局时，请按类别制作专用 ZIP；专用根中的普通子目录仍按导入类别处理。`composite` 只是溯源标记，不是第四类知识库。

公开合成模板只用于验证格式和检索链路，不含临床知识，也不能替代你自己的合法资料。

## 6. 借助 AI 一步步建构自己的知识库

本节面向只有文献、尚未拥有现成知识库的 clone 用户。目标是让 AI 协助你生成可导入本系统的分类 ZIP，而不是让 AI 凭空编写一套资料。文献和工作目录放在仓库外；不要读取真实 `.env`、健康记录或照片，也不要把生成的私有 ZIP 提交到公开仓。

### 6.1 准备文献与工作目录

1. 准备你有权使用的 PDF、文本、Markdown 或网页资料。扫描件若无法读取，应让 AI 明确标记，不要猜测内容。
2. 先选定本包类别：`constitution`（体质/体征/辨证资料）、`diet`（食疗与饮食宜忌）、`formula`（方剂、方证与煎服资料）。同一文献可以按主题分别进入不同类别，不要把无关章节硬塞进一个包。
3. 在仓库外新建工作目录，例如 `my-kb-work/constitution/`。可复制 `templates/kb/` 作为结构起点，但不要修改项目模板，也不要把其中的合成占位内容当作实际资料。

### 6.2 先让 AI 建立“主题—出处”清单

不要一开始就要求 AI 生成最终 ZIP。先让它读取指定资料并输出清单：

| 字段 | 含义 |
| --- | --- |
| 主题 | 准备写入的具体主题，不追求覆盖整本书 |
| 建议文件名 | 如 `notes/topic.md`，使用相对 POSIX 路径 |
| 来源位置 | 书名、版本、章节、页码或 URL；无法确认时留空并标记 |
| 内容性质 | 原文节选、忠实摘要或自己的说明，三者不得混淆 |
| 未处理内容 | 无法读取、找不到依据或存在歧义的部分 |

检查清单是否覆盖了你需要的主题、来源位置是否可追溯。没有来源支持的内容不要让 AI 补齐，也不要把其他知识库的内容混入新包。

### 6.3 分批生成 Markdown

让 AI 按清单逐主题写作，避免一次处理整本书导致漏读或混淆出处。每个文件使用第 2 节的来源元数据，并用清晰标题和小节组织：

```markdown
# <主题>

来源：<书名、作者、版本、页码或 URL>
许可：<你确认的使用许可或授权依据>
整理日期：<YYYY-MM-DD>
整理说明：<原文节选、忠实摘要或自行说明>

## <小节>

<与上述来源对应的正文>
```

不要求固定医学章节或 front matter；检索读取真实文本行。原文节选与摘要必须分别标明，模型生成内容不得标成原文，不确定内容不得写成确定事实。保留关键语境、适用条件和限制，不要为了便于检索把复杂内容压成无条件结论。

### 6.4 让 AI 生成别名词典

词典用于把查询扩展到资料中确实存在的同义表达，格式见第 2 节。要求 AI：

- 优先使用资料实际出现的规范词，再连接你明确知道的同义口语。
- 不因为两个词“意思相近”就建立别名，不使用过宽词、通用症状词或互相矛盾的概念。
- 每个映射保留依据；无法确认时宁可不加。
- 原查询会自动保留，不需要在别名列表中重复。
- 不修改评分词表、红线、权重或剂量规则；别名只扩展检索。

### 6.5 填写分类清单

每个分类包的根目录必须有 `kb.yaml`，并与准备导入的类别一致：

```yaml
schema_version: 1
# 按实际类别改为 diet 或 formula
category: constitution
name: <你的资料名称>
source: <来源说明>
license: <使用许可或授权依据>
```

不要添加未知字段、嵌套字段或重复字段。若制作综合包，综合导入不强制清单；若提供清单，类别必须为 `composite`。

### 6.6 检查文件并打包

1. 将实际 Markdown、根目录 `kb.yaml` 和可选的根目录 `synonym_map.yaml` 放入工作目录。
2. 若复制了合成模板，替换或删除 `example.md`，不要把占位示例带进实际知识库。
3. 对照第 2 节检查编码、路径、文件数和大小；`kb.yaml` 与根词典不要只存在于子目录。
4. 在工作目录的上一级执行以下命令，将目录内容打入同名 ZIP：

```bash
python -c "import shutil; shutil.make_archive('constitution', 'zip', 'constitution')"
```

`constitution` 换成你的实际目录名；三类分别打包。原工作目录和 ZIP 都应保留，不要把唯一原稿放进系统的导入副本目录。

### 6.7 导入系统

打开「设置 → 知识库」，在对应分类卡片中选择 ZIP 并提交。无需配置模型，也不要把 ZIP 移动到程序管理目录。导入成功后，确认状态为“知识库可用”，并检查可检索 Markdown 数是否符合预期。

设置页会显示状态和文件数；完整路径在“技术详情”中。导入、覆盖或重置处理的是程序管理副本，不会删除你原来的文献目录或 ZIP。每类分别导入，互不影响；严格分类模式应在这三类专用包分别验证后再开启。

### 6.8 验证是否真正对接

按第 5 节做三项最小检查：

1. 用资料中确定存在的词检索，确认命中预期文件和段落。
2. 用词典中的口语键检索，确认别名扩展和来源正确。
3. 用报告中出现的候选参考回到本地来源抽查，确认没有因为“格式通过”就把无关内容当作相关资料。

同时记录未能读取的页面、未处理主题和无法确认的别名，不要把它们静默省略。若导入失败，先修正 ZIP 或清单，不要通过修改系统规则绕过校验。

### 6.9 可复制给 AI 的任务提示词

把下面提示词交给能够读取你指定本地资料的 AI agent；替换方括号内容。AI 应先报告实际读取范围，再生成文件，不要假装通读了无法访问的资料。

```text
任务：根据我提供的文献，为本中医望诊系统制作一个分类知识库。

项目文档：先阅读 docs/KB_AUTHORING.md 和 templates/kb/README.md。
文献位置：[本地文件、目录或 URL]
工作目录：[仓库外的输出目录]
本包类别：[constitution / diet / formula]

请按以下顺序执行：
1. 只读取我明确提供的资料。先列出实际读取的文件、页码/章节范围，以及无法读取的部分；不要从记忆补充缺失内容。
2. 先输出“主题—出处”清单，字段包括主题、建议文件名、来源位置、内容性质和未处理内容。未经我确认，不要直接打包。
3. 清单确认后，按主题生成 UTF-8 Markdown。每份文件包含来源、许可、整理日期和整理说明；原文节选、忠实摘要和自行说明分别标明，不把生成内容伪称为原文。
4. 保留来源中的适用条件、限制和歧义。找不到依据的内容标记为未处理，不猜测，不用其他资料补齐。
5. 按文档生成根目录 kb.yaml，category 必须与上述类别一致，schema_version 为 1，不添加未知字段。
6. 如确有必要，生成根目录 synonym_map.yaml。别名只连接有明确同义依据的词，不使用过宽映射，不修改评分、红线、权重或剂量规则。
7. 检查 README.md 不作为检索正文；若使用合成模板，替换或删除 example.md。
8. 按文档检查路径、编码、文件数和大小，使用 zipfile 将目录内容打成 ZIP，报告 ZIP 路径、文件清单和未能处理的内容。

只操作我指定的工作目录，不读取或修改真实配置、健康记录、照片或其他知识库，不上传到公开仓。最后给出导入后应测试的术语、别名和来源抽查清单。
```

### 6.10 完成判据

一份包可以进入系统验收，至少应满足：

- 实际读取范围、来源位置和未处理内容均有清单，没有虚构出处。
- Markdown、词典和 `kb.yaml` 符合第 2 节，文件类别与导入表单一致。
- ZIP 在设置页导入成功，状态与文件数符合预期。
- 确定存在的术语和词典别名均能命中预期来源，无命中时不伪造结果。
- 原工作目录、来源文件和 ZIP 均保留，系统只管理导入副本。
