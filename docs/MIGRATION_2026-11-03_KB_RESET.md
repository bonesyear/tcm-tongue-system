# 分类知识库重置与重新启用（v1.19.0）

**日期**：2026-11-03
**范围**：设置页新增分类重置，并把每次上传明确为“完整校验后重置旧副本、激活新内容”。只处理程序管理的导入副本，不修改外部原始知识库。

## 1. 重置目标与安全边界

每类重置只处理固定路径 `<TCM_DATA_ROOT>/private_kb/<类别>/`，不会根据当前 `TCM_KB_ROOT` 或类别专用根寻找删除目标。外部原库、综合库和其他类别均不受影响。

目标不存在时仍可执行停用，属于幂等操作。目标不是普通目录或是符号链接时拒绝操作，避免沿链接删除外部内容。环境变量锁定根或停用键时拒绝重置，避免页面宣称已停用但实际仍由环境配置启用。

## 2. 停用语义

新增变量：

- `TCM_KB_CONSTITUTION_DISABLED`
- `TCM_KB_DIET_DISABLED`
- `TCM_KB_FORMULA_DISABLED`

重置将其设为 `1`，并把该类根指向本类导入目录。停用优先于专用根和综合库回退，因此重置后对应信息确实不可显示，不会被旧综合库重新激活。

新 ZIP 在完整校验、清单检查、暂存激活成功后清除停用标记并恢复检索。上传语义不是先删除再校验，而是先完整验证，再重置旧副本并激活新副本，坏包不会改变旧状态。

## 3. 重置事务

`web/kb_reset.py` 先将旧副本移动到 `.kb-reset-backup-<随机串>/`，只有配置成功标记为停用后才删除备份。失败时恢复旧副本和配置；配置回滚也失败则明确报错，不宣称已恢复。

上传和重置共用 `web/kb_config_tx.py` 的配置字节快照：恢复原文件内容，而不是只恢复原键值，避免新增空配置键。若原文件不存在，失败回滚会移除本次新建文件。事务备份已加入 `.gitignore`。
