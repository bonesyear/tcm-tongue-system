## 1. 显式未配置不再回退外部综合库

### 现象与根因

类别闸门已经返回 `None`，且三类状态均为 `unconfigured` 时，`inspect_kb(None)` 仍从 `TCM_KB_ROOT` 重新取得外部旧根。设置页因此误显示综合库可用，报告也可能检索并发送被默认忽略的内容。

根因是无参数调用与显式 `None` 共用一个默认值，无法区分“使用环境默认”与“上游已判定未配置”。

### 行为与兼容性

- `inspect_kb()`：保留原有环境变量和默认目录行为。
- `inspect_kb(None)`、`inspect_kb("")`：直接返回 `root=""`、`status="unconfigured"`、0 文件和空版本，不再读取环境默认。
- Web 报告显式传递各类根；类别为 `None` 时不检索。准备前后的版本复核使用同一语义。
- 旧 `(model, base_url, api_key)` 三元组及完全未提供知识库键的底层调用保留原默认行为；显式 `kb_roots` 中的空值不回退。
- 外部目录是否允许使用仍由 `kb_category_root()` / `kb_legacy_root()` 决定，本次没有放宽该闸门。

## 2. 照片提交失败完整回滚当前部位

`commit_photos()` 原先在暂存图转正成功后才登记当前部位。如果旧图已经移入备份，而后续备份或转正失败，当前部位不在回滚清单中，旧图不会自动恢复。

现在先登记当前部位，再执行旧图备份与暂存图转正。任一步失败都会恢复本轮已移动的旧图和暂存图；后续记录版本冲突仍走原有整体回滚。

## 3. 相对目录也遵守规范正档优先

目录扫描返回绝对路径，规范正档比较却使用调用方原始相对路径，导致相对目录调用无法识别 `{date}_analysis.json`。当另一候选文件更新时，系统会误选非规范副档。

规范路径现统一转为绝对路径后比较。非规范候选的 mtime 选择、副本排除、告警与缓存行为不变。
