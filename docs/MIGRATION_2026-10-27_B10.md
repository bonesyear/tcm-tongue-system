## OSS 备份

`scripts/backup_to_oss.sh` 现在同时以 git 跟踪清单和敏感路径规则筛选文件。敏感文件即使曾被跟踪，也不会进入压缩包；`records/`、`charts/`、`.env`、`.privacy-words`、`_books/`、PDF/EPUB、任务文档和 `.claude/` 均排除。`.env.example` 可保留。

- 未设置 `TCM_OSS_BUCKET` 时在上传前直接退出，不再默认使用作者桶。
- 哈希与打包都使用相对路径，避免上层目录名含 `records/` 或 `charts/` 时永久跳过备份。
- 清单缺少 hash 时给出可诊断提示并重新备份；清单以同目录临时文件原子替换。
- 白名单通过 NUL 分隔的 git 路径传给 tar，不额外递归目录，避免“白名单 + 整目录”重新装入敏感文件。

## pre-push

新增 `scripts/hooks/privacy_scan.py`，由 `pre-push` 对每个真实新增提交及附注标签调用：

- `git rev-list <local_sha> --not --remotes=<remote>` 计算提交集合，覆盖根提交、中间提交、force push、linked worktree 和附注标签，不再只检查 tip。
- 解码 UTF-8/UTF-16，折叠大小写并补 JSON Unicode 转义变体；检查文件内容、路径、提交与标签消息。
- 检查常见凭证模式和配置指纹，路径分隔支持 JSON 数组及 `os.pathsep`，不再依赖作者固定的单一路径。
- 图片做原始字节检查，未知二进制、缺失词表、不可读配置等都不能静默通过。
- 日志只输出规则编号、变量名及脱敏位置，不输出敏感词、完整 key 或命中行。仅扫描器自身的正则定义在匹配前移除，其他文件没有目录豁免。
- `VERSION` 与 CHANGELOG 最新版本继续强制一致，提示统一为不带 v 的版本号。

## push.sh

- 保留 credential 配置及 include 内容，只净化 URL 重写；include 使用临时净化副本，原文件不被改写，嵌套深度受限。
- 全局、系统配置都处理；仓库级 `url.insteadOf` 和非 GitHub 目的地直接拒绝，不宣称“直连成功”。
- 用被推送分支的 `refs/heads/<branch>` 计算本地 SHA，以 `ls-remote` 独立读取远端，不 fetch 到本地 tracking ref 自证；远端失败或不一致都不能输出成功。
- `GIT_BIN` 是测试注入点，默认值为 `git`，生产行为不变，不是新增外部依赖。
