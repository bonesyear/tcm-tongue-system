# 知识库运行链与无库展示修复（v1.16.1）

**日期**：2026-11-03
**范围**：修复全面审查发现的知识库配置断裂、无库误导、报告版本与引用语义问题。不重写医学底层模型，不改变原始知识库、医学权重或方剂/剂量闸门。

## 1. 配置根与统一状态

此前设置页从 `.env` 读取 `TCM_KB_ROOT`，报告却调用无参 `retrieve()`，只能读取进程环境或默认目录。现由 `web/app.py` 在同次配置快照中把 `kb_root` 交给报告生成，再传入 `_kb_references()` 和 `retrieve()`。

新增 `src/retrieval/kb_status.py` 的 `inspect_kb()`，统一返回：

| 状态 | 含义 |
| --- | --- |
| `unconfigured` | 未显式配置，默认公开目录没有可检索 Markdown |
| `empty` | 已配置目录，但没有可检索 Markdown |
| `ready` | 目录可读取且有可检索 Markdown |
| `error` | 目录不存在、不是目录或读取失败 |

`file_count` 用于设置页，`revision` 是路径、大小和 `mtime_ns` 的轻量签名，不宣称是逐字节内容哈希。大写 `.MD` 现在也能被列出和检索，与导入器一致。

## 2. 报告生成与版本

报告新增元数据：

- `kb_status`：生成时的 `unconfigured / empty / error / no_hits / retrieved`；
- `kb_root`：本次实际检索根；
- `kb_revision`：本次版本签名；
- `kb_error`：发生错误时的限长诊断（如有）。

调用模型前再次检查根和版本，准备期间发生变化则返回错误并要求重试。读取详情时，`report_state()` 比较当前与报告保存的根/版本，变化时增加“知识库目录或内容已变化”的过期原因。

旧报告没有这些字段时，不仅凭知识库变化强制判过期；页面显示“知识库状态未记录”，避免伪造历史溯源。已有 `kb_refs` 继续兼容读取，但语义改候选参考。

## 3. 无库前端契约

- 设置页明确区分未配置、空库、可用和错误，不再只用默认路径和 0 文件暗示状态。
- 模型输入明确说明无库、无命中或错误，不得宣称建议已通过库内校核；报告页同步显示。
- 本地速览的聚类、分值和 `DIET_MAP` 内容不变，但改称“项目内置规则映射”。用户界面不再展示当前不可核验的 `KB L…` 或 `diet-therapy.md` 行号。
- 内置规则的代码维护注记和版权归属未删除、未重新裁决；仅停止把它们包装成当前知识库证据。
- 0 维覆盖显示“暂无已采集观察”；未知项显示“未知/待复核不等于未见异常”；只有真实覆盖且无阳性时才使用带未覆盖提醒的阴性倾向文案。
- 报告尾部改称“知识库候选参考”，明确送入模型不等于模型实际引用。没有结构化引用 ID 对照，不再声称每条都是实际出处。

## 4. 降级与输入限制

可选 `synonym_map.yaml` 缺失属于正常降级，不再逐次打印告警；文件被删除后不会继续复用旧别名。格式错误和不可读仍告警，且错误缓存避免重复刷屏。

候选条文按单条 1200 字、总计 12000 字限制，文件路径和命中词也限长。模型输入明确条文是不可信资料，不执行其中指令；这降低超长输入和提示注入风险，但不证明能抵御全部恶意文献。

知识库无否仍不参与置信度或方药/剂量闸门，本批仅补状态披露。是否调整该医学安全策略须另行明确决定。
