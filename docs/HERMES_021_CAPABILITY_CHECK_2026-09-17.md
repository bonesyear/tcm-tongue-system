## 三、图片输入模式机制（`agent/image_routing.py`）

`decide_image_input_mode(provider, model, cfg)` 的判定顺序（`agent.image_input_mode` = `auto` | `native` | `text`）：

1. 非 `auto` → 直接返回该值（**`native` 是绝对覆盖**）
2. `auto` 且存在**显式 `auxiliary.vision` 后端** → 返回 `text`（即：辅助视觉模型先描述，主模型读文本描述）
3. 否则看 `supports_vision`（配置覆盖或 catalog）→ `native` / `text`

代码注释另指出：`models_dev.py:593` 把 `deepseek-flash` 视为 unknown → **会 fallthrough 到 lossy text**。

**本项目当前状态**：`config.yaml` 设 `image_input_mode: auto` **且**显式配置了 `auxiliary.vision`（qwen3.8-max）→ 走 `text` 模式，与现有「2a 分类 + 2b 观察」链路一致。

## 八、A/B 实测结论（2026-09-18，首次真实舌照）

同一天的真实舌面照 + 舌底照，两条路径使用**完全相同的 prompt**。

### 8.1 速度与合规

| 项 | A. Qwen3.8-Max（现行 text 链路） | B. deepseek-flash（native） |
|---|---|---|
| 舌面耗时 | 35 s | **13 s**（快 2.7 倍） |
| 舌底耗时 | 19 s | **6 s**（快 3 倍） |
| JSON 合规 | ✅ | ✅ —— **但 `max_tokens` 必须 ≥ 8000**（真实舌照 reasoning 占 2200–2900 token，设 3000 时输出被截断、JSON 解析失败） |
| 图像 token | prompt 2261 | prompt 1156 |

### 8.2 判读一致性

**一致项**（✅）：舌色（淡红）、苔色（白）、苔润燥（润）、苔腻腐（不腻）、剥落（无）、裂纹（中央浅沟判为生理性正中沟）、**舌下络脉（颜色/粗细/走行三项全部正常，两模型完全一致）**。

**程度措辞差**（⚠️）：胖瘦（Qwen「胖大」vs native「稍胖」）；齿痕（Qwen「无」vs native「不明显」，实际倾向「不明显」）。

**实质分歧**（❌）：**点刺** —— Qwen 判「无」，native 判「舌尖及中前部可见少量红点」。

> ⚠️ **更正（2026-09-18 补充实验）**：本次 Qwen 的「无」是**少数采样命中，不是稳定能力**。同日用同一档案照片（`img_a612a31a1f2d`）复测 9 次（新 prompt ×6：不传 temperature 3 次 + temperature=0 3 次；旧 prompt ×3），点刺 **9/9 判「有」**，且 temperature=0 不消除。即点刺字段**两个模型均不可靠**，本次分歧不构成判读能力差异的证据。详见 8.6。

### 8.3 用户裁定与结论

**用户肉眼裁定（最终权威）：点刺无。**

~~Qwen 判对，native 过度判读~~ → **该论据已证伪撤回**（见 8.2 更正：Qwen 同图 9/9 判「有」，首轮「无」为少数采样命中）。进一步复核四个分歧项对照档案最终签认值：

| 分歧项 | Qwen | native | 档案签认值 | 更接近者 |
|---|---|---|---|---|
| 胖瘦 | 胖大 | 稍胖 | **偏胖** | native（稍胖） |
| 齿痕 | 无 | 不明显 | **不明显** | native |
| 点刺 | 无（首轮） | 有少量红点 | 无 | 均不可靠（9/9 证伪） |
| 舌底三项 | 完全一致 | 完全一致 | 正常 | 平局 |

**原「Qwen 判读质量更优/更保守」的论据证据不足，予以撤回**：四个分歧项里 native 有 2 项更接近签认值、1 项两模型都不可靠、舌底三项完全一致。

> **结论：维持 Qwen 为识图主力（方向保留，立足点改为运营性理由）。**
> ① **prompt 已按 Qwen 调校**：「中央沟判生理性」「舌底不过度判读」等保守规则已写入现行 prompt 与规范，切换模型需重新调校验证；
> ② **不扩大隐私面**：真实舌照目前只发送给百炼（Qwen），切 native 需把真实舌照发给 DeepSeek——按既定纪律须用户当场确认；
> ③ **切换成本 vs 收益**：native 每次快约 30 秒（2.7–3 倍），收益有限，不足以抵消重新调校与隐私面扩大的成本。
> 若未来要重新评估，须以**用户肉眼**为裁定基准、重复测量（同图 n≥5/模型、温度固定），而非单次采样。

### 8.4 附带发现：细粒度体征对提问方式敏感

结构化 JSON prompt 下模型倾向快速给出「无」；换用**聚焦追问**（如「请聚焦舌尖与舌边区域描述」）后，**同一模型（Qwen）会报出「散在轻度红点、部分看似轻微隆起」**。

→ 说明点刺这类**细粒度体征**受提问方式影响显著。处置原则：**以用户肉眼为准**；需要复核时要求模型**聚焦指定区域**再判，并把两轮结果都记录下来（不要只取首轮）。

### 8.5 评分词表缺口（已签认，2026-09-18 修复）

`src/scoring.py` 的 `TONGUE_BODY_SIZE_MAP` 原 **未收录「偏胖」**（临床常用表述）→ 本次档案 `body_size: "偏胖"` 落空得 0 分，属**漏判**。

**最终分值（用户签认）**：偏胖 4、偏瘦 4、稍胖 3、略瘦 3（既有 适中 0 / 胖大 7 / 瘦小 6 / 肿胀 9 不动；硬约束偏胖 ≤ 7，否则「偏胖大」平局翻转）。复合词「胖嫩/瘦薄」**不收**——混入老嫩维度，走识图 prompt 规范化（只取胖瘦成分：胖嫩→偏胖、瘦薄→偏瘦）或辨证层。详见 `docs/REPAIR_PLAN_2026-08-25.md` 轮次 7。

### 8.6 采样稳定性补充实验（2026-09-18，同图 9 次）

同一档案舌面照 `img_a612a31a1f2d`，三组各 3 次（注：组间为顺序执行，存在时间/负载混杂；每组 n=3，字段级差异只作方向性参考）：

| 组 | 条件 | 评分层面抖动字段 | 点刺 |
|---|---|---|---|
| A | 新 prompt，不传 temperature | 腻腐（微腻/微腻/腻）、胖瘦（偏胖/偏胖/胖大）、齿痕（无/无/轻度） | 3/3 判「有」 |
| B | 新 prompt，temperature=0 | 腻腐仍抖（无/腻/腻，3 次出 2 种结果）——**temp=0 不消除抖动** | 3/3 判「有」 |
| C | 旧 prompt（无齿痕/点刺规范化句） | 腻腐（微腻/微腻/无） | 3/3 判「有」 |

**要点**：① 点刺 9/9 判「有」vs 用户肉眼「无」——系统性偏向；**跨图复测（2026-09-18 实验 2）**：同一用户另一张舌面照（8-09，同人）`temperature=0` ×5 也 **5/5 判「有」**，两图合计 **10/10**，即该模型对「有红点的舌面」一致报「点刺」，**无输出不确定性**（注：两图均属「有散在红点」情形，故只证明对该作者一致判有，不能证明判有率与真值完全无关；8-28 真值「有」的照片已丢失，无法做真值对照）。**术语层根因**：VLM 的判据是「有没有红点」而非「红点是否凸起增大」，而舌尖/舌边**正常蕈状乳头即呈红点状**→ 系统性假阳性；② 润燥「润/润泽」属措辞抖动、评分同为 0，不计入评分抖动；③ 腻腐是三组全抖的唯一字段，但属**判断层面**抖动，封闭词表只能保证评分映射确定、不能消除判断摇摆；④ 新 prompt 的点刺规范化句（「不填『不明显』等」）拆掉了模型存疑时的对冲出口，使系统性偏向直接落成 5 分假阳性——已于 2026-09-18 恢复安全阀（存疑可填「不明显」）并将点刺退出评分层（见 `CHANGELOG.md` v1.4.3）。
