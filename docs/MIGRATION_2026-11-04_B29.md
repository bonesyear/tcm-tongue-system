# B29 统一视图归属与缓存完整性（v1.20.20）

**日期**：2026-11-04

**范围**：独立复核分类知识库与完整综合库的输出一致性，修复重复文件类别归属、说明目录枚举和已发布缓存完整性。只改变统一视图的构建、校验与缓存失效，不修改知识库正文、医学规则、评分、权重或剂量策略。

## 1. 知识库差分结论

综合知识库与三类 ZIP 均先复制到工作区隔离目录，再通过现有 `import_kb()` 导入独立副本。比较只针对可检索正文，不读取真实配置、健康记录或外部模型。

- 综合库与分类并集均有 7 个可检索 Markdown；相对路径、正文 SHA-256 完全一致，无缺失、额外、改动或冲突文件。
- 综合词典及三个分类词典均有 72 个键。查询集由默认锚词、全部词典键、额外 OR/AND 与无命中查询组成，共 82 个。
- 对三种单类、三种双类及完整三类共 7 种组合分别比较，合计 574 组直接 `retrieve()` 输出；Grep/RAG 方法、命中数、文件、行号、正文、上下文、排序和别名展开全部一致。
- 各组合 `_kb_references()` 候选内容、顺序和 `build_report_input()` 文本一致。正式 `generate_and_store_report()` 使用本地假模型捕获输入，完整综合库与分类库的提示词、10 条候选及三类状态完全一致。
- 差分前后 ZIP 隔离副本、解压副本和分类副本字节不变。该结论针对确定性检索与模型输入，不宣称真实模型逐字输出或医学准确性一致。

## 2. 重复路径的类别归属

**现象与根因**：不同专用根含相同相对路径、相同正文的文件时，检索只保留一份是正确的，但旧实现由后处理根覆盖 `owners`。完整综合根按标准目录归类的同一候选，在分类视图中可能进入另一类别，导致报告输入不同。

**修复**：重复且同内容时，若标准目录类别属于重复来源之一，沿用该类别，与综合根一致；专用根普通目录无法判类时保留确定性的首个归属。不同内容的同路径冲突继续明确拒绝。

## 3. 文件枚举与说明目录

**现象与根因**：复制层使用 `Path.rglob()`，检索层使用 `list_kb_files()`。后者会排除名为 `README.md` 的目录及其后代，前者却收录其中的 Markdown，造成所有者清单大于检索文件集合，已发布视图在下次加载时被判无效并重复复制。

**修复**：构建和版本计算统一复用 `list_kb_files()`，使文件、目录排除与链接处理只有一个实现。小写 `readme.md` 仍按正文检索，既有语义不变。

## 4. 已发布正文与派生索引完整性

**现象与根因**：旧清单只记录所有者和别名，加载只比较文件路径集合。已发布 Markdown 内容损坏仍会通过校验；如果损坏期间已建立 RAG，单独重建正文也会让旧索引继续返回污染文本。

**修复**：`_VIEW_SCHEMA` 升为 2，清单增加每个 Markdown 的 SHA-256。当前视图加载时复核正文，损坏则重建；淘汰扫描只做结构校验，避免对所有历史视图重复哈希。重建同路径前调用 `invalidate_kb_caches()`，同步删除文件行、词典与 RAG 派生状态。缓存与源根重叠时的一次性视图行为不变。

该校验防止意外损坏被静默采用，不把本地可写缓存视为抗恶意篡改的安全边界；人工清理仍须先停止服务。

## 5. 回归与全量验证

- 新增 4 个回归：重复文件类别及报告输入一致、说明目录不导致重复构建、损坏正文自动恢复、污染 RAG 在重建后不再返回旧文本。修复前均复现对应缺陷。
- 知识库、统一视图与报告聚焦：**74 passed**；全量：**1067 passed、1 skipped**。
- 修复后重新执行隔离知识库副本差分，574 组检索、7 种组合、正式报告输入继续全部一致，隔离文件与 ZIP 字节不变。
