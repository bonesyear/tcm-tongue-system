## 3. 生产部署

`web/requirements.txt` 新增 Web 专用 `waitress==3.0.2`，核心 `src/` 仍不引入该依赖。`web/app.py` 的 `main()` 通过 `web/server.py` 启动生产 WSGI 服务，不再直接调用 Werkzeug 开发服务器。

- `threads=8`：固定工作线程池。
- `connection_limit=64`、`backlog=32`：限制连接与排队。
- `channel_timeout=300`：处理不活跃连接，不替代视觉/辨证模型自身的总时限。
- `max_request_body_size`：与现有图片上传限制加表单余量一致，避免服务器与应用上限不一致。

默认仍监听回环地址；`--lan` 与自定义非回环地址仍要求管理口令，Host/Origin/会话校验不变。此配置不把系统声明为公网安全服务，也没有把模型供应商验证或真实多设备验证冒充为已完成。

## 4. 同日报告去重

`trends_store.generate_and_store_report()` 按“绝对数据目录 + 日期”使用进程内锁：

- 同日已有报告生成时，新请求立即返回 `ok=false, in_progress=true`，路由映射为 **409**，不重复调用收费模型。
- 首份生成、读取、写回全过程持锁；成功、校验失败或模型异常均在 `finally` 释放。
- 锁只解决同一进程同一日期的重复生成，不冒充跨进程去重或重复扣费保证。主动在完成后重新生成仍是原有功能。
