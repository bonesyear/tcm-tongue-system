# B11 Web 同源、鉴权、XSS 与响应边界（v1.13.4）

**日期**：2026-10-27
**范围**：Web 请求闸门、局域网认证、监听地址、JSON 类型、前端注入与响应头。不改变医学权重、预警规则、剂量策略或记录结构，不引入新依赖。

## 必须执行的迁移

1. **先配置管理口令，再开放非回环监听**。在设置页「访问与安全」填写 `WEB_ADMIN_TOKEN`；口令和 `WEB_HOST` 可以同次保存。也可在启动前通过环境变量或 `.env` 配置。`--lan` 或其他非回环地址无口令时会拒绝启动，不再仅显示警告。
2. **用设置页表单登录**。手机打开设置页显示的局域网地址，在「管理口令验证」中输入口令。旧的 `?token=口令` 不再作为凭据，也不会注入表单或 JavaScript；请不要继续使用带口令的书签。
3. **重新确认须知**。`/settings/login` 成功后建立 `admin_session`，但 welcome 的 `boot_ack` 是独立确认。首次进入或重启后按页面引导完成即可；须知确认本身不授予局域网数据权限。
4. **使用页面显示的地址和端口**。服务仅接受 localhost、回环地址、已配置监听地址及探测到的局域网地址作为 Host。不要改用自定义域名、其他端口或伪造 Host/Origin。当前监听与下次启动地址在设置页分别显示。

## 请求边界

- 所有请求（包括 GET）先校验 Host；不合法或不受信任的主机名直接返回 403。局域网 IP 探测失败时不会把空主机名加入白名单，失败方向保持关闭。
- POST、PUT、PATCH、DELETE 拒绝 `Sec-Fetch-Site: cross-site`，并校验 Origin/Referer 的协议、主机和端口与当前请求一致。localhost 的不同端口不视为同源。
- 某些浏览器会发送 `Origin: null`。只有同时携带明确的 `Sec-Fetch-Site: same-origin` 才允许这一窄回退；缺失 Origin、`null` 无同源元数据、`same-site` 或 `cross-site` 都不能借此通过。不是接受任意 `null`。
- 普通写请求在没有来源头时可凭有效 `boot_ack` 或 `admin_session` 兼容传统浏览器；`/welcome` 初次确认没有会话可依赖，必须有同源 Origin/Referer 或上述同源 Fetch Metadata。
- 回环地址保留本机便利流程。`X-Forwarded-For` 不会把远端请求提升为本机；未配置受信代理解析时，带转发头的请求需要管理会话。IPv4-mapped 回环地址按回环识别。

## 局域网认证与数据

- 非回环访问 `/settings` 未验证时为只读，并提供带可见标签的口令 POST 表单。
- `/settings/login` 使用常量时间比较验证口令，成功时签发加密随机的进程内 `admin_session`；错误口令返回 403，不签发会话。
- `admin_session` 与 `boot_ack` 都是 HttpOnly、SameSite=Strict cookie；HTTPS 请求另加 Secure。会话保存在当前服务进程内，重启后失效。
- 未认证的局域网设备不能读取首页、记录、趋势、向导或照片，也不能加载示例、修改配置或调用模型。设置页只读不等于健康数据公开。
- 口令只从 POST 表单或 JSON 请求体读取，不再从 URL 查询参数读取。保存后的重定向不携带口令。
- 默认 HTTP 不提供传输加密，仅限可信局域网，不得直接暴露公网。Secure 属性依赖实际 HTTPS 请求；本批没有引入反向代理、HTTPS 或 HSTS。

## 输入与响应边界

- 使用 JSON 的写接口要求请求体为对象。数组、字符串、数字、布尔值、`null` 和畸形 JSON 均返回 400；无 JSON 请求体保留原有默认参数行为。
- `WEB_HOST` 仅接受 `localhost`、IPv4 或 IPv6 地址。保存和 CLI 启动使用同一校验；无口令的非回环地址拒绝，IPv6 横幅地址加方括号。
- 连通性测试返回的 `data.detail`、向导预警的名称/规则/证据/说明以及手动录入警示，不再与 HTML 字符串拼接。改用 `createElement`、`textContent` 和 `replaceChildren`，保留原有警示分类、已见/还缺和复核出口。
- 增加 `X-Frame-Options: DENY`、`Content-Security-Policy: frame-ancestors 'none'`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和 Fetch Metadata 的 `Vary`。这只是防嵌入与配套边界，不宣称已经部署完整脚本 CSP 或 Trusted Types。

## 验证与未覆盖范围

- `tests/test_web_security.py` 覆盖伪造 Host/Origin、端口和协议差异、不透明 Origin 的允许/拒绝分支、跨源写入、错误口令、URL 口令失效、伪造会话、健康数据和照片门禁、代理头、监听地址、JSON 类型及响应头。
- 原 Web 测试中的 welcome POST 已改为显式同源请求；本机正常流程保持有效。
- Flask 实际渲染的 `/settings`、`/wizard` 内联脚本均通过 `node --check`，显式 UTF-8 避免 Windows 子进程按 GBK 编码。
- 真实内置浏览器以临时数据根、假口令、模拟局域网来源和本地模型 stub 验证：welcome → 错误口令 → 正确口令 → 首页 → 设置 → 向导。伪造 `<img>` 错误文本只作为文字显示，DOM 中没有对应 `img` 元素。临时标签、服务及配置目录均已清理。
- 未进行真实多设备双窗、真实公网 HTTPS、反向代理或真实模型调用验证。全部测试使用临时目录、合成数据和 stub，不读取真实 `.env`、健康记录、照片或历史病案。
